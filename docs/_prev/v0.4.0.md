## 1. 做了什么

### 1.1 记录原因（场景 JSON）
| 内容 | 字段 | 说明 |
|---|---|---|
| 每个物件 | `id`、`gid`、`group`、`reason`、`anchor`、`exp`、`novel` | 例如 `front:b7` / “露天座位的桌子：贴着立面、避开门前通道” / 锚点 `door b7.door (x, y)` |
| 小组 | `scene.groups[]` | 类型、实例、触发原因、锚点、成员、外框 |
| 建筑 | `scene.buildings[]` | 外框、碰撞体积、门、打包原因（“第 31 行是最低的空行……立面临街 → 可为店铺”） |
| 区域 | `scene.zones[]` | 禁放区、通行带、车道、内院用途、路缘段（包括“这条街不放设施”）、车行道、横道 |

| 参数 | `scene.options` | 创新度、实验总开关、逐个开关 |

### 1.2 标注显示（快捷键 A）
![标注层](v0.4.0/ui_anno_seed7.png)

- **小组层**：按类型着色的实例框，放大后显示 gid。
- **悬停 / 单击详情**：精灵缩略图、类别、小组、原因、触发、锚点连线（黄色虚线）、同组成员高亮（黄框）。点建筑会显示外框、碰撞体积、门和打包原因。
- **区域层**：回答“这里为什么是空的”。禁放区用斜线填充，其余区域用淡色填充。单击空地会列出覆盖该点的所有区域及原因。
- 图例与筛选：图层开关，小组类型和区域类型可以逐个勾选。
- 实验内容：粉色粗虚线加“实验 exp-NN”标签。新贴图：青色点线加“新”字。下图用手工改过的场景 JSON 测试了这两种样式（目前还没有真正的实验功能和新贴图）。

### 1.3 好 / 坏标注工具
![标注工具](v0.4.0/ui_labels.png)

- **选择目标**：单击物件或建筑；Shift+拖动框选区域；单击空地则选中一格。
- **标记**：按 `1` 标为好，按 `2` 标为坏；选预设标签，填写原因，Ctrl+Enter 保存。右侧列表可以定位或删除已有标注。
- **存储**：`references/labels/v<版本>/seed<种子>.json`，由 `npx vite` 开发服务器直接写入。第一次标注时，同时保存该场景的 `.scene.json`。没有开发服务器时暂存在浏览器里。
- **标注内容**：版本、种子、创新度、完整参数、好 / 坏、标签、文字，以及目标（矩形、物件 id / 精灵 / 坐标快照、gid、区域 id）。
- **导出（E）**：PNG、`_ghost.png`、**`_annotated.png`**（3 倍放大，含当前图层和全部标注）、scene JSON；有标注时再附 `_labels.json`。
- 把任意 scene JSON 拖进查看器即可原样查看。

### 1.4 实验功能框架
- 登记表：`app/src/gen/exp.ts` 与 `docs/EXPERIMENTS.md`，目前为空。
- 开关：顶栏“实验 ▾”提供总开关和逐个开关，也可以用 URL 参数 `x=0` 和 `e=exp-01:0`。
- 每个实验用独立随机流 `exp/<id>`，并通过 `withExp` 给产物打标记。
- 用一个临时登记的实验测试过：开关逻辑正确；创新度 0 时 200 次触发 0 次，创新度 1 时 200 次触发 200 次；物件、小组和区域都带上了实验编号。
- 创新度滑块（默认 0.10）已经接入，并记录在导出和标注中。阶段 7 之前它不影响生成。
