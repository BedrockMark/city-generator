# 项目需求：有机城市街区生成器

> 2026-11-01 更新（v0.3.0 之后）。阶段 1–3 已完成，本次新增阶段 4–7。
> 方法现状见 `docs/methodology.md`，决策记录见 `docs/NOTE.md`。

## 背景
我想在 Phaser 引擎中程序化生成像素风城市地图。我提供了完整的素材库，以及 46 张用同一批素材手工拼制的参考地图。

最早的尝试失败了：生成结果是规整网格上整块复制粘贴的街区（见 `anti_references/`），完全没有参考图的有机感。我会继续往该文件夹放入反面案例，格式由你决定。

截至 v0.3.0，生成器（规则驱动的分层程序生成）的结果已基本合格，但仍偏方正。更大的问题是**修改方式**：我挑出样本、用文字描述优缺点，再由你把描述翻译成新的生成规则。新规则常在别的种子上生出不合理的东西（画蛇添足，例如楼间出现不通向任何地方的通道），细节越改越难。本次更新的目的，是把迭代方式从“口头描述 → 加规则”改为“标注 → 约束 / 评判 → 学习”。

## 目标
- 最终目标：生成完整的城市。
- 当前阶段：生成**单个高质量的地图区块**，即由道路围合的一个街区，尺寸与参考图相近。质量优先，方法不限，速度和代码优雅度次要。

## 素材说明
- 每格 16×16px。
- 大部分素材同时提供单张（文件夹内每张是一个建筑模块 / 装饰品 / 变种辅助）和整合图（文件夹名 + `.png`）。
- `assets/` 下约 3000 张素材，保持素材包原始结构，文件名包含类别、尺寸和变体信息。
- 许多是拼好的复合物件（如整个面包店底层门面），可以替换更小的图块组合出变体。
- 以脚本批量分析为主，只在必要时抽样查看图片。

## 参考图说明
- `references/` 下是参考图。GIF 只取第一帧（动画留给后续阶段）。
- 最外侧的 UI 边框、右侧的素材展示栏需裁掉，不得作为生成内容使用。
- 参考图完全由 `assets/` 中的素材拼成，像素一致。
- 参考图之间主题差异很大（商业街、运河区、住宅区等），不要假设共享同一套规律；有时是同一组素材的颜色变种。
- 我会把合格的产出存档到 `references/holdout/`，格式由你决定，用于学习和验证。

## 我说的“有机”
以下是我的观察，并不完整，请继续从参考图中发现：
- 物件之间有强烈的功能和叙事关系：公交站牌、站亭和地面标线成组出现；店门口有对应的桌椅、招牌和顾客；垃圾桶在巷口；消防栓在路缘。每个物件都“有理由出现在那里”。
- 街面层较小，但很密、很热闹，没有大片无意义的空地。
- 整体不重复：任何局部都不应像是从别处复制来的。
- 我最在意**主体之间的关系**，地形细节可以简化。

## 硬性要求
1. 不得直接复制参考图中的大片段，结果要像“同一位设计师画的新地图”。需有检验方法。
2. 随机种子可复现；不同种子之间差异明显。
3. 在 Phaser 中可直接查看，可重新生成、导出截图。
4. **可解释**：每个物件、建筑和刻意留空的区域，都能说明所属小组和出现原因。
5. **实验性内容可识别、可关闭**（定义见下文）。

## 工作原则（新增）
1. **分工**：生成器负责提议；约束检查和评判器负责判断；修复器负责局部改正。我的反馈优先变成标注数据和约束，不优先变成新的生成规则。
2. **回归验证**：任何生成逻辑改动，都要在固定的回归种子集（约 200 个）上报告前后变化，包括约束违规数、评判器得分，以及我已标注的好 / 坏区域是否受影响。只看几张图不算验证。
3. **宁删勿补**：局部修不好时，降级为朴素填充（草坪、灌木、空地面），不要补更多东西。
4. 评估指标与我的判断不一致时，改指标，以我为准。

## 实验性功能（定义）
我会不时请求实验性功能，例如创造性的模块化建筑、新的街区形式。要求：
- 每个实验功能有唯一编号（如 `exp-03`），在 `docs/EXPERIMENTS.md` 登记：内容、开关、状态。
- 由实验功能产生的物件、建筑和区域，在场景 JSON 中带上实验编号，在标注层中用醒目的独立样式显示，让我一眼看出“这是实验功能造成的”。
- 可全局关闭，也可逐个关闭。关闭实验功能时，同一种子的其余部分尽量不变（利用独立随机流）。
- 状态分三种：实验 → 转正 / 废弃。依据是我对该功能产物的好 / 坏标注；转正或废弃前先向我确认。

## 创新度参数（定义）
- 一个 0–1 的参数，查看器中可调，随导出记录。默认取低值，0 表示完全保守。
- 创新度越高：
  - 越偏好使用少用或从未用过的贴图（使用次数统计来自参考图和历史生成结果），被选中的“新贴图”在标注中单独标记；
  - 实验功能的启用概率越高；
  - 评判器对“不熟悉”内容的惩罚相应放宽，避免学到的偏好把新东西全部过滤掉。
- 无论创新度多高，硬约束（连通、不重叠、模块拼装合法等）始终生效。

## 阶段
每个阶段结束时停下，汇报并等我确认后再继续。

### 已完成：阶段 1–3
分析、原型、迭代至 v0.3.0。

### 阶段 4：可解释与标注
不改变生成逻辑，同一种子的画面不变。
1. **记录原因**：每个放置补上 `gid`（小组实例，如 `bus#0`、`front:b7`）、`reason`（一句说明）、`anchor`（锚点：门、横道、路缘段）。每个小组登记一条记录：类型、实例、锚点、触发原因。建筑记录外框、碰撞体积和打包原因；禁放区、通行带、车道等区域也带原因。随机决策统一经过 `choose(label, context, options)`，把决策轨迹写入场景 JSON。
2. **标注显示**（快捷键 A）：小组层（按类型着色的实例框）、悬停 / 点击详情（精灵、类别、小组、原因、锚点连线、同组高亮）、区域层（“这里为什么是空的”）、图例与筛选。实验内容和新贴图使用独立样式。
3. **好 / 坏标注工具**：点选物体或建筑，或框选区域，标记好 / 坏并填写原因（预设标签 + 自由文字）。标注须包含版本、种子、创新度、涉及的 `gid` / 物件 id、区域矩形。存储格式由你决定。导出时附 `_annotated.png`。
4. 建立实验功能登记和开关框架。

### 阶段 5：合理化后处理
1. 构建功能连通图（门、人行道、马路、内院、物件之间的可通行关系）。
2. 声明式约束清单，例如：门可达、过道连接两个有意义的端点、垃圾箱靠近后门或服务通道、长椅前方不是墙。初版由你从参考图和我的标注中总结，交我确认后生效。
3. “存在理由”剪枝：追溯不到街道、门或建筑的元素被删除或降级。
4. 回归种子集和报告脚本；我标为“坏”的案例自动转为约束测试用例。

### 阶段 6：局部评判器与修复
1. 训练数据：参考图的局部窗口（正）、我的好 / 坏标注、被接受的样本。先用可解释特征 + 简单模型，数据足够后再考虑更复杂的模型。
2. 输出整图“怪异热力图”。
3. 局部修复：对得分最低的区域换子种子重新生成多个候选，取约束通过且得分最高者；修不好则降级。
4. 向我报告评判器学到的主要规律，供我核对。

### 阶段 7：从选择中学习 + 创新度
1. 用标注和 A/B 选择调整生成参数，以及各决策点在不同上下文下的选择权重，替代手写新规则。
2. 实现创新度参数（定义见上）。
3. 实验功能的转正 / 废弃流程。
4. 说明哪些问题无法靠“选择”解决（选择只能重新加权已有的提议，例如“方正”需要扩展提议空间），并提出相应的提议扩展方案供我选择。
