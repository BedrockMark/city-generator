# v0.8.1：区块 API、Worker 池和查看器城市模式

2026-11-11，分支 `main`。v1.0.0 城市生成的第二个里程碑（spec `docs/superpowers/specs/2026-11-11-v1-city-design.md` 第 10 节，计划 `docs/superpowers/plans/2026-11-11-v081-chunks-viewer.md`）。

这一版有了查看器的城市模式：在浏览器里拖动、缩放着漫游一座 v0.8.0 的城市，进入任一街区做好 / 坏标注。单街区模式（查看器、`generate(seed)`）完全不变：200 个回归种子 200/200 相同。

## 1. 做了什么

### 三个 API（`app/src/world/chunk.ts`）
世界切成 64 × 64 格（1024 px）的区块，每个区块由拥有它格子的街区拼出来。区块是（种子，cx，cy，选项）的纯函数，和缓存状态、请求顺序无关（测试：清缓存、倒序后逐项相同）。

| 函数 | 做什么 |
|---|---|
| `getChunk(seed, cx, cy, opts?)` | 一个区块：`ground`（层 × 64 × 64）、`height`（现在全是 0，留给 v1.0.0 的高度）、`objects`（`ownerCell` 在本区块的物件，按 (foot, sub) 排好序，id 和 gid 带街区前缀）、`blocks`、`missing`（没生成出来的街区，那几格用世界地面） |
| `getBlock(seed, blockId, opts?)` | 一个街区的完整 `Scene`（窗口场景，进入街区标注时用） |
| `worldInfo(seed, x, y)` | 世界格 (x, y) 的说明：类别、街区、拥有者、分区、`z`（分区噪声值）、`level`、`why[]`（悬停说明用） |

另有 `assembleChunk(seed, cx, cy, block)`（街区由调用方提供，Worker 里用）、`trimBlock`（只留区块组装需要的部分，便于在 Worker 之间传）、`chunkRect`、`chunkOf`。

### Worker 池（`app/src/viewer/`）
- `pool.ts`：固定大小的 Worker 池（大小 `poolSize(cores)`，上限 `WORKERS_MAX`），忙的时候排队，回复按 id 对应。
- `city.worker.ts`：三种消息：`block`（生成一个街区，返回裁剪后的 `CityBlock`）、`chunk`（用主线程发来的街区组装区块）、`scene`（一个街区的完整场景）。
- `cityqueue.ts`：纯函数的任务调度（无 Phaser、无 Worker API）：视口里的区块按离中心的远近排序，两步走：先把区块需要的街区发给空闲 Worker 生成，街区到齐的区块再发去组装；换种子 / 退出城市模式时 epoch 加一，旧结果丢弃。
- `city.ts`（类 `CityMode`，城市部分）和 `draw.ts`（从 `main.ts` 搬出来的画图函数，单街区和城市共用）。

### 城市模式的操作
- 工具栏左边的“单街区 / 城市”切换；城市模式有“世界种子”输入框，网址参数 `?city=1&seed=<种子>&x=<格>&y=<格>&z=<缩放>`。
- **拖动**平移；**滚轮**缩放（0.25–4；单街区仍是 0.25–8）；**F** 回到默认缩放。
- 鼠标悬停：右上角的信息栏显示 `(x, y) · 分区 · 层 · 街区`。**单击**选中 / 取消选中一个街区（描出轮廓），并打开 `#cityPanel` 显示 `why` 说明，Esc 取消选中。
- **双击**一个街区（或选中后按 **Enter**、点“进入街区”）进入街区：生成该街区的完整场景（不会自动打开标注层，按 **A** 打开；之后和单街区一样可做好 / 坏标注、看小组 / 区域 / 约束图层），信息栏显示 `世界 <种子> · 街区 <id>`。标注存到 `references/labels/v<版本>/seedw<种子>_<街区id>…scene.json`（存放键 `storeKey`，NOTE D86）。
- **Esc**：先取消选中；街区视图里再按 Esc 回到城市，相机恢复；街区还在生成时按 Esc 取消进入。
- **E** 导出：当前屏幕的快照（一张 PNG 加一份 JSON，不是把所有区块拼起来）（`citygen_v0.8.1_world<种子>_x<x>_y<y>_z<z>`）。

### 脚本
- `scripts/cityregress.ts`：世界回归。每个种子的 5 × 5 个区块（世界格 [-128, 192)²）用 `getChunk` 生成，查接缝、物件唯一、局部性、马路连通、人行道通马路，写 `report.md`；失败退出码 1。`--jobs n` 并行，`--base` 带上单街区快照做对比。种子集 `scripts/city_seeds.json`（1–20）。
- `scripts/shots.ts` 加了 `--city x,y,z`（可重复）：按城市模式截图并导出。

## 4. 已知问题

1. **同一行相邻区块的大精灵排序**：同一行的相邻区块共用同一个深度 `cy`，横跨左右区块边界的大精灵可能排错前后（spec 第 6 节接受这个代价）。
2. **城市模式没有“虚化楼上层”和网格**（街区视图里有）。
3. **失败的街区在同一 epoch 里不重试**：这个区块用世界地面画那个街区，直到重新进入城市模式或换种子。
4. **缩放 0.25 时显存吃得多**：每个区块 2 张约 1024 px 的 RenderTexture（各约 4 MB 以上），一屏最多约 11 × 8 个区块；`CHUNK_KEEP=2` 时视口外的区块还会留着，常驻的区块可达 100 多个，即 200 多张 RenderTexture，约 1 GB 级，在 6 GB 以下的显卡上可能吃紧。没有改代码。
5. 街区视图里隐藏 +/−/适应 按钮（滚轮和 F 仍可用）；很长的悬停说明可能被 `#info`（宽 32vw）截断。
6. 区块组装 53–82 ms，略超 50 ms 的目标。
7. v0.8.0 的遗留：种子 1 的 `b-1,1/LRRR` 没有楼（用户说不用修，见 v0.8.0-hotfix1 报告第 7 问的回答、NOTE D82）。

## 5. 要你看的问题

1. **在查看器里漫游**：`cd app && npx vite`，打开 `http://localhost:5173/?city=1&seed=1`（或点“单街区”旁的切换）。拖动、滚轮缩放、悬停单击看说明，感觉流畅吗？画满一屏的等待时间在你的机器上能接受吗？
2. **标几个街区**：双击进入街区，用好 / 坏标注标一些（标注存到 `references/labels/v0.8.1/`）。世界层的街区（大小、人行道、街区之间的衔接）有什么要改的？
3. 是否要优先修已知问题 1（相邻区块的大精灵排序）或 2（城市模式虚化上层），还是继续 v0.8.2（繁荣度、大街区中心广场、环岛）？
4. **世界区域的街区质量比单街区差**（验收 5 未达到）：每街区剩余违规 0.162 对 0.05，约 3 倍，其中 C18 × 5 是修复失败。要先查原因（世界区域的窗口 / 邻居约束），还是先放着做 v0.8.2？
5. **一屏画满的时间**（验收 7 未验证）：请在你的浏览器里打开城市模式，读信息栏的“一屏画满 x.x 秒”，告诉我缩放 1 / 0.5 / 0.25 各是多少。
