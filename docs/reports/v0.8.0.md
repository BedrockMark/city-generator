# v0.8.0：世界层（分区、主干道、支路切分、地面）和街区窗口

2026-11-11，分支 `main`。v1.0.0 城市生成的第一个里程碑（spec `docs/superpowers/specs/2026-11-11-v1-city-design.md` 第 10 节，计划 `docs/superpowers/plans/2026-11-11-v080-world-layer.md`）。

这一版还没有查看器的城市模式（v0.8.1），城市只能用脚本导出成一张大图看。单街区模式（查看器、`generate(seed)`）完全不变。

## 1. 做了什么

### 世界层（新目录 `app/src/world/`）
全部是纯函数：输入世界种子和格坐标，随机数来自坐标散列（`hash.ts`），不依赖计算顺序，任意一块可以单独算（NOTE D73）。坐标是整数，可以是负数，1 格 = 16 px。

| 文件 | 做什么 |
|---|---|
| `config.ts` | 世界层所有概率、权重、尺寸（spec 3.8）。其它文件里没有这些数字；路宽集合 `ROAD_WIDTHS`、`REGION_PAD` 由别的常量推出来（NOTE D78） |
| `zone.ts` | 分区噪声：两层平滑插值的值噪声（主干道格间距一层 + 3 倍间距一层，权重 0.5），≥ 0.62 闹市，< 0.38 住宅，其余混合 |
| `arterials.ts` | 主干道：横竖两组线，间距 120 × 88 格，每条线偏移 ±12 格；宽度每条线散列抽一种（竖 5 / 7 / 9，横 5 / 7），整条一样宽；相邻两个路口之间整段平移 0–2 格（错位） |
| `blocks.ts` | 支路和街区：每个主干道格按格中心的分区递归地用 5 格宽的支路切开，直到每块地块在分区的目标范围里（闹市 18–34 × 13–25，混合 20–36 × 14–26，住宅 22–40 × 15–28）。切刀以 25% 的概率在中途错开 2–4 格（错开后切不出合法的 L 形时不错开，实际约 12% 的切刀错开），得到 `jog` 街区（NOTE D76）。街区 id `b<i>,<j>/<切分路径>`，每个街区带分区、人行道宽（闹市 3，其余 2）、铺地和 `why` |
| `cells.ts` | 每格的类别（马路 / 人行道 / 地块）、马路格的归属（最近人行道所属的街区，路口也一样，NOTE D74）、横道（每个路口的每条臂按散列决定，主干道 45%、支路 30%） |
| `ground.ts` | 世界地面：沥青、人行道和地块铺地（autotile）、中线虚线、横道。和单街区的画法一样（同一套选块函数），两张相邻的图重叠部分逐格相同 |
| `window.ts` | 街区窗口：一个街区 + 四周 14 格，翻译成现有生成器的 `Layout`，用现有的流水线生成，再丢掉站在别人格子上的物件（NOTE D75） |
| `region.ts` | 把一个矩形里的所有街区拼成一张场景（世界地面 + 每格归属街区的地面改动 + 物件 / 楼 / 小组 / 区域，id 加街区前缀） |

### 生成器的小改动（`app/src/gen/`，不传新参数时一切不变）
- `generateBase(seed, opts, win?)`：可选的窗口参数。有窗口时用窗口的 `Layout`，不生成邻近街区（`planNeighbours`、`nfronts`、`island`），场景 `params` 加上 `world: { seed, blockId, zone, offset }`。
- 限高：`Layout.topLimit`，打包器保证楼的精灵最上一行不高过北边马路的中线（spec 4，用户确认）。只在城市模式里有。
- `layout.ts`：道路分段的分析拆成 `findSegs`，横道 / 虚线的选块拆成 `zebraTile` / `dashTile`，世界层直接复用；`slab` 在负坐标上取模改成非负。单街区画面不变。
- 城市模式的创新度固定 `CITY_NOVELTY = 0.10`（spec 3.9）。

### 脚本
`cd app && npx tsx scripts/cityshot.ts ../work/city080 <种子> [x0,y0,w,h]`（默认 `-60,-44,360,264`，约 3 × 3 个主干道格）写出 `city_<种子>.json` 并打印统计；然后 `cd tools && uv run python render_generated.py ../work/city080/city_1.json --scale 1` 出 PNG（5760 × 4224）。每个种子约 45 秒（生成街区约 42 秒，平均每个街区 0.35 秒）。

## 5. 已知问题

1. **小物件依赖窗口的形状**（NOTE D77）：现有生成器的随机流按窗口里的相对坐标取标签（花园的位置、路缘设施、停的车、区域的 `x0, y0`），马路 / 人行道 / 横道 / 车的一部分抽签在整个窗口上顺序进行。所以窗口大一圈，花园、路缘设施、停车这些小物件会换一种；楼不变。每个街区的窗口只由（种子，街区 id）决定，所以结果仍然确定、局部可算。以后（`getChunk` 时）可以改成按世界坐标取标签，但那会改变 v0.8.0 的城市画面。
2. **种子 1 的街区 `b-1,1/LRRR` 没有楼**：闹市，地块正好是最小的 18 × 13，生成器的打包（`planMainBlock` / 打包器）一栋楼都没放下，只放了停车场、花园、巷子和广场。问题在生成器里，不在世界层；矩形里完整的 77 个街区中只有这一个。
3. **横道按路口的每条臂散列**（`CROSSING_CHANCE`，主干道 45%、支路 30%），不是单街区模式里“每个路口 0–2 条”的抽法，所以有的路口四条臂都有横道，有的一条都没有。
4. **jog 的切法**（NOTE D76）：错开的一侧（L 形）还可以继续被平行于错开的那条支路的直刀切开；每个街区最多错开一次；所有切刀中错开的约 12%。
5. **矩形边上的车行道区域**：车行道区域（`carriageway`，只是标注层的说明，不画出来）按每个街区拥有的那一段切开，中心落在矩形外的那段在这张图里丢掉，所以矩形边上的一小段马路没有说明区域（种子 1 的 28160 个马路格里 23944 个有）。物件也是同样的规则。
6. 城市图里一条路的车行道区域被切成好几段（每个街区一段），标注层会看到更多、更短的车行道区域。
7. 每个种子约 45 秒；主要是逐个生成街区（约 0.35 秒一个）。v0.8.1 的 Worker 池会并行。

## 6. 要你看的问题

1. **路网间距**：主干道格 120 × 88 格（约 3 × 3 个街区），偏移 ±12 格。主干道是不是太密 / 太疏、太规整？
2. **街区大小**：地块中位约 26 × 17 格（和单街区模式差不多）。要不要更大或更小，或者某种分区单独调？
3. **分区过渡**：现在一个主干道格整格一种分区（按格中心），三种分区的差别只有街区大小、人行道宽和铺地（楼型要到 v0.8.2）。片区的大小（种子 2 几乎没有住宅）合适吗？
4. **jog 的观感**：错开 2–4 格，约 12% 的切刀（种子 2 有 30% 的街区是 jog）。像参考图吗？要多一点、少一点，还是只在某种分区里？
5. **哪些常量想调**：都在 `app/src/world/config.ts`（第 1 节的表）。告诉我数字就行。
6. **横道**：按每条臂 45% / 30% 散列，可以接受吗？还是要像单街区模式那样每个路口 0–2 条？
7. **先修什么**：已知问题 1（小物件随窗口变，改成按世界坐标取标签会改变 v0.8.0 的画面）和已知问题 2（小闹市街区没有楼）要不要在 v0.8.1 之前修？
