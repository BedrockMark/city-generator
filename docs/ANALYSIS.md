# 阶段 1 分析报告：参考图规律、方法与风险

> 日期：2026-11-01　｜　状态：等待你确认后进入阶段 2（原型）
> 所有数字都可以用 `tools/` 下的脚本复现（见文末“工具清单”）。中间产物在 `work/`，插图在 `docs/fig/`。

## 0. 一页摘要

1. **地图结构 = 网格图块层 + 自由物件层。** 地面和建筑严格对齐 16px 网格；车辆、路灯、标牌、垃圾桶、长椅等多数**不对齐网格**，按像素放置。生成器必须同时支持这两层。（实测：market_on_street 的 Market 建筑正好落在网格相位上，而路灯/标牌的 x mod 16 分别是 5、9、11、12 …）
2. **“有机感”的来源可以拆成可执行的规则：** 物件沿路缘排成“节奏带”；功能小组（vignette）围绕一个锚点出现（路口、店门、公交站、施工坑、停车位）；局部对称、整体不对称；同一组合在同一张图里会**押韵而不是复制**（同类小组出现两次时，部件和朝向都会变）。
3. **参考图之间几乎不共享大片段：** 不相干参考图之间 4×4 图块窗口共享率 = 0%。已知的近重复组（shopping_centre ×2、apartment ×2）共享约 40%，这正好说明检测器有效。图内自我重复率 ≤ 10.5%。这两个数字会作为后续“没有抄袭、没有复制粘贴感”的硬性验收线。
4. **参考图都不是完整街区。** 19 张 street 类参考图都只是街区的局部视角（20×17 到 47×42 格）。道路宽度能测：**双车道 5–6 格，路缘到路缘**；宽路口 9–11 格。人行道 1–6 格。区块的整体尺寸只能推断，需要你确认（见第 6 节问题 2）。
5. **推荐方法：** “叙事优先的分层程序生成”。地块划分 → 建筑由模块拼装 → 由锚点触发功能小组 → 路缘节奏带 → 填充/去空洞 → 约束检查。用参考图统计出的数字来校准参数，用自动指标（抄袭、自我重复、密度、关系一致性）加上你的眼光来验收。

### 3.2 定性规律（看图得出，统计辅助）

1. **路缘节奏带（rhythm strip）。** 人行道靠路缘一侧的 1–2 格是“设施带”：路灯、行道树（方形树池）、花箱、护柱、消防栓、信号灯、标牌都排在这里。排列有**节拍**：
   - simple_resident_complex：花箱与护柱交替，每 48px 一个单元；
   - simple_street_corner：Pole_1 每 48px 一个；
   - 树每 32–44px 一棵。

   节拍会被“事件”打断，比如入口、人行横道、公交站。节拍两端常用路灯收尾。（`fig/curb_rhythm.png`）
2. **锚点 → 功能小组（vignette）。** 每个小组都围绕一个“理由”：
   - **路口**：人行横道 + 两侧成对红绿灯 + 杆上的过街标志（蓝色行人牌）+ 井盖。人行横道往往**对准**对面的入口或建筑门。market_on_street 里，人行横道正对 Market 的门轴线。（`fig/crossing_axis.png`）
   - **店门**：门前 1–2 格有 A 字牌 / 菜单牌，门侧有垃圾桶，橱窗下有花箱。餐饮店另有桌椅、遮阳伞、顾客。
   - **公交站**：候车亭 + 公交站牌 + 等车的人，附近有垃圾桶。（`fig/bus_stop_trash.png`）
   - **垃圾点**：2–3 个大垃圾箱贴着围栏或建筑侧面，加上散落的垃圾袋，常在地块后侧、街角或停车场边。
   - **停车**：画线车位 + 部分车位有车（不是全满）+ 入口处的 P 牌和箭头 + 附近的咪表/充电桩。
   - **施工 / 道路维修**：坑 + 路障 + 锥桶 + 安全帽散落；工地用橙色网围栏，门口有标牌，围栏外有流动厕所。（`fig/road_works.png`）
   - **建筑设备**：空调外机、电箱、管道贴在建筑侧墙；屋顶有空调、天线、晾衣架、太阳能板。
3. **局部对称、整体不对称。**
   - neighborhood：喷泉两侧树木成对对称；
   - hotel：入口两侧的花箱和路灯镜像，两组道路维修也分列两侧；
   - school：入口台阶两侧对称摆放盆栽。

   但整张图从不整体对称。（`fig/symmetry_fountain.png`）
4. **押韵而不是复制。** 同类小组在同一张图里出现两次时，组成部分会变：hotel 左侧是两个路障 + 两个锥桶，右侧是一个路障 + 三个锥桶 + 安全帽。街区内重复出现的建筑会更换窗型、店招、颜色。量化依据：图内 4×4 窗口自我重复率 ≤ 10.5%。
5. **街面层小而密。** street 类图每 100 格约 3–26 个高置信度物件（中位约 5.5）。这里的分母包括被建筑占据的格子，按可见地面算会更密。看图的感觉是：任何一段 4–6 格长的人行道上至少有一个物件，空地只出现在“有理由空着”的地方（车道、人行横道口、门前通道）。
6. **地面本身也有叙事。** 不同地块用不同的铺装（瓷砖 / 鹅卵石 / 人字砖），有小块草地、磨损斑点、刹车痕、井盖、排水格栅。同一套人行道素材有 6 种颜色变体，同一张图里通常只用 1–2 种。
7. **遮挡与绘制顺序。** 视角是俯视加正面。高建筑会画到它北侧的道路/人行道上（neighborhood_with_construction 的建筑盖住了道路），所以物件要按脚底 y 坐标排序绘制。
8. **人物。** 参考图里的人是叙事的重要部分，详见 3.3。

### 3.3 人物（`assets/charactors`，2026-11-01 新增）

**素材结构：**
- 分层：身体 → 眼睛 → 服装 → 发型 → 配饰。成人共 12 种身体、7 种眼睛、140 套服装（39 组）、200 种发型、93 种配饰；儿童另有一套；另有书、手机道具。
- 帧网格：16×32 帧，56 列。成人 20 行动画（预览、站立、行走、睡、坐 ×2、看手机、看书、推车、捡起、送礼、举、扔、被打、出拳、刺、拿枪、持枪、射击、受伤），站立和行走都是 6 帧 × 4 方向；儿童只有 4 行。
- `PG_*`（320×96）是另一套头像生成器，不用于地图。
- 合成器和编目：`tools/characters.py`。主题标签：`tools/character_themes.json`，每条都注明了证据来源（参考图实测 / 目测）。

**参考图里的人（`tools/detect_characters.py`、`char_stats.py`）：** 在 42 张图里检测到 125 人，召回率大约七到八成（人工对照 town_near_river：约 25 人中检出 19 人）。有少量误检，比如头套匹配到垃圾箱。

- **主题服装只出现在对应场所：**
  - 警服（组 29）+ 警帽 → 两张警局图、河边小镇；
  - 邮差服 + 邮差帽包 → 邮局；
  - 泳装（组 31/32）→ 海滩、舞台、泳池；
  - 童装 → 游乐场、学校、住宅区；
  - 童子军 → 森林、郊区；
  - 西装（组 05/06）→ 公寓、酒店、医院、加油站；
  - 工人头盔 → 工地。

  其余约 60% 是便装，到处都可以出现。→ 生成器规则：**区块主题和地块程序决定“职业人”的配额，其余人随机便装。**
- **姿势和物件配对：** 坐姿的人 28px 以内几乎都有桌子 / 长椅（21 个桌子、5 个长椅邻近）。看手机、行走的人在人行道上，靠近垃圾桶、树、路灯。站立的人围着车辆、摊位、标牌。
- **成群：** 85 人单独出现，24 人两人一组，16 人三人一组。town_near_river 的热狗车前有 4–5 人的人群，面朝摊位。
- **人物是锚点的一部分：** 店主站在摊位 / 售货亭里面，顾客在柜台前，等车的人在候车亭下，坐着的人在长椅和餐桌旁，窗口和阳台里也有人（town_near_river、suburb_neighborhood_1），警察守在警局门口和屋顶。没有人站在毫无理由的空地上。
- **密度：** street 类图每张 0–19 人，按可见面积大约每 30–60 格 1 人，比道具稀疏得多。

## 4. 打算采用的方法

### 4.1 主方案：叙事优先的分层程序生成（推荐）

整体流程（全部由种子化 RNG 驱动，同一种子结果可复现）：

1. **街区骨架。** 选定区块尺寸，四周是道路（5–6 格，或某一边为 9–11 格主干道），加路缘、人行道（1–3 格，可局部加宽成前庭），四个路口按需放置人行横道。地面图块用 autotile 规则拼接（路缘、圆角、草地边缘）。
2. **地块划分（不规则）。** 沿四条街面切分地块，面宽从建筑模块可用的宽度集合中抽样，有意避开等分。街角地块单独处理。内部可留后巷 / 内院 / 停车场。每个地块分配一个“程序”：商店、餐饮、公寓、办公、独栋住宅带院子、停车场、小广场、工地……分配时按街区主题的分布抽样，并带邻接约束，比如两个餐饮不相邻、停车场不正对主入口。
3. **建筑拼装。** 用 `5_Floor_Modular`（底层店面 + 中间层 + 屋顶）、`4_Generic_Buildings`、`24_Additional_Houses` 等模块拼装，宽度、层数、颜色、店招、窗型各自独立抽样。这样同一类建筑出现两次时外观自然不同（押韵而非复制）。屋顶道具在屋顶区域内随机放置。
4. **锚点 → 功能小组。** 每个地块根据自己的程序产生锚点：门、侧墙、后院、车道口；道路边产生路口、公交站候选、停车段。每类小组是一个**参数化语法**，不是模板。以店门为例：

   ```
   店门小组 = 门前通道(保持空) + 1 个立牌(偏左或偏右, 0–1 格) + [餐饮? 桌椅组×1–3] + [垃圾桶 50%] + [花箱×0–2]
   ```

   部件的种类、数量、左右、距离都随机，再用统计出来的偏移分布校准。
5. **路缘节奏带。** 每条街面选一个节拍（32 / 44 / 48px）和一个“韵脚”序列（树–灯–树、花箱–护柱…）。遇到入口、人行横道、公交站、车道时断开，两端收尾。四条街面的节拍和韵脚各不相同。
6. **填充 / 去空洞。** 检查人行道上超过阈值的连续空白，用和上下文相关的低优先级物件填补：井盖、垃圾、花盆、标牌、消防栓（贴路缘）、自行车……填补物必须挂在某个“理由”上，比如垃圾挂在垃圾点附近，消防栓挂在路缘带。
7. **约束检查与修复。** 不重叠；门前和人行横道口保持通行；物件不压在路缘线上；同类小组相隔太近时换变体；最后按脚底 y 排序绘制。
8. **Phaser 前端。** 生成器用 TypeScript 写，跑在浏览器里，方便“重新生成”按钮即时响应。界面上有种子输入、重新生成、导出 PNG 截图，以及导出 scene JSON（格式与分析工具相同，可直接交给 `novelty.py` 等检查）。

**参数从哪里来：** 道路/人行道尺寸、各类物件与路缘/建筑的距离、成对关系与 lift、节拍间距，都来自第 2–3 节的统计；小组语法的骨架由我手写。数据太少（19 张局部 street 图），不足以让模型自己学出结构，但足够校准参数。

## 5. 备选方案与风险

| 方案 | 优点 | 风险 / 为什么不作为主方案 |
|---|---|---|
| **A. 主方案（分层程序生成 + 参数化小组语法 + 统计校准）** | 关系可控，可解释；天然不抄袭；种子之间差异大 | 需要写不少规则，“有机感”取决于小组语法的质量；可能出现“规则味”（太整齐）。缓解：所有节拍和偏移都加抖动，并用押韵 / 打断机制 |
| B. 基于样例的合成（WFC / 重叠模型 / 图块马尔可夫链，从参考图学习） | 局部纹理很像参考图 | 容易拼出参考图片段（违反硬性要求）；无法处理不对齐网格的自由物件；学不到功能关系。**只考虑用于地面细节**（铺装斑块、草地边缘） |
| C. 关系学习 + 优化布置（从检测结果学成对势能，用 MCMC / 模拟退火摆放，类似室内布局合成） | 关系由数据驱动，摆放更“自然” | 数据量小（约 1,400 个物件，分散在很多主题里），学到的势能噪声大；调试困难。**作为 A 的第 6–7 步（填充 / 微调）的增强手段**，在迭代阶段引入 |
| D. 生成式模型（扩散 / GAN 直接出图或出布局） | — | 46 张图远远不够；像素级输出无法保证完全由素材拼成；难以复现。**否决** |
| E. 直接从参考图抠出小组模板，随机摆放 | 快 | 本质上就是拼贴，抄袭检测会报警；也正是反例“复制粘贴感”的来源。**否决**；小组只能是参数化语法 |

**其他风险：**

- **模块化建筑拼装规则。** 左 / 中 / 右段、楼层衔接、店面替换，需要逐类摸清，否则会有接缝。缓解：先只用少数几套模块，渲染后人工核对，再扩展。
- **Autotile 拼接。** 路缘、草地边缘用的 GMS 47 格规则需要正确实现。
- **遮挡与绘制顺序。** 高建筑会盖住北侧的街道，要按脚底 y 排序。
- **分析误差。** 约 5% 的低置信度误检已排除，但类别规则是按名字关键词写的，个别类别统计会有偏差。重要的数字我都人工核对过。
- **“有机”是主观的。** 第一版原型极可能“太整齐”或“太乱”，需要你的反馈来定方向。

## 6. 需要你判断的问题

1. **第一个区块的主题？** 推荐**商业 / 混合街区**（店铺 + 公寓 + 小停车场 + 一个路口），因为 street 类参考图大多是这类。也可以先做住宅（独栋 + 院子 + 公交站）。
2. **区块尺寸？** 推荐内部约 28×20 格，四周半条道路，整图约 34×26 格（544×416 px）。要更大（比如 40×30）也可以。
3. **人物：** 新增的 `assets/charactors` 已分析完（3.3 节）。原型里打算把人当作**功能小组的一部分**来放：店主、顾客、等车的人、坐长椅的人、成群的人。职业服装按区块主题配额，其他人随机便装，静止帧用站立、坐、看手机。动画留到后续阶段。这样可以吗？
4. **生成器语言：** 用 TypeScript 写在浏览器里（重新生成即时，Phaser 原生），分析和评估工具继续用 Python。可以吗？
5. **存档格式建议：**
   - `references/holdout/`：放 **PNG 截图 + 同名 `.json`**（viewer 导出的 scene JSON，含种子和生成器版本）。只有 PNG 也行，我会用分析管线重新识别。
   - `anti_references/`：PNG 即可；如能附上 scene JSON 和一句文字说明“哪里不好”，最有用。
6. **4 张 200×112 的缩略图：** 有原尺寸版本吗？没有也不影响。
