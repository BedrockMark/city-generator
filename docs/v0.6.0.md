## 1. 改了什么
- **评判器**（`app/src/gen/judge/`）：给每个 8×8 格窗口（128px，步长 4 格）打“怪异分” = 这个窗口有多不像参考图。
  - 先把生成图降到参考图的“视力”：地面按图块颜色分类，楼按整张精灵算墙，物件用同一套 17 类，去掉人物和被楼挡住的物件（D40）。
  - 23 个可解释特征，L1 逻辑回归，你的 v0.5.1 标注作为加权样本并入（D42）。阈值 0.675 = 参考图窗口得分的 90 百分位。
- **热力图**（查看器快捷键 H）：红色越深越怪，黄框 = 超过阈值的窗口，青色虚线框 = 修复过的窗口（标着修复前 → 后的分数）。悬停显示分数和前 3 个原因。
- **exp-02 评判修复**（默认开，`e=exp-02:0` 关闭）：
  - 目标：超阈值的窗口，以及 C19 / C23 / C24（只报告的约束）违规所在的窗口，每张图最多 3 个；
  - 对窗口里的随机流换盐，重生成 6 个候选，只采用“约束不变差、窗口外不变差、目标窗口变好”的候选；
  - 都不合格就降级（花园改草坪、只留植物、删弱锚点的装饰物），且降级必须真的降分（D44）；
  - 修复产生的物件带 `exp-02` 标记，标注层里能看到；导出的场景 JSON 记着采用的盐，能原样重现。
- **整体档**（`jg=1`，默认关）：再试 6 种主街区打包，每种都走一遍局部档，整图平均分更低且约束不变差才采用。
- 查看器的生成挪到 Web Worker，修复时顶栏显示进度。exp-02 关闭时，200 个种子的画面和 v0.5.1 完全相同。

## 2. 评判器学到了什么（等你核对）
完整的表在 `JUDGE.md` 第 3 节，每条规律都附了参考图和生成图各一个例子。权重 > 0 表示“生成图特有，越多越怪”。

| # | 特征 | 权重 | 规律 |
|---|---|---|---|
| 1 | 草地占比 | −0.56 | 参考图草地更多，生成图偏少 |
| 2 | 长直边 | +0.44 | 生成图的草地 / 铺地边界多是 ≥4 格的长直线 |
| 3 | 标牌密度 | −0.42 | 参考图标牌、路牌更多 |
| 4 | 最大空地 | +0.33 | 生成图常有一大块没有物件的空地 |
| 5 | 站在马路上 | −0.32 | 参考图里车和井盖以外的物件也会站在马路上 |
| 6 | 贴墙 | +0.24 | 生成图的物件更常贴着楼 |
| 7 | 植物密度 | +0.19 | 生成图树和植物更多 |
| 8 | 同一贴图重复 | −0.18 | 参考图在一个窗口里更常重复同一张贴图 |
| 9 | 同类扎堆 | −0.13 | 参考图同类物件更常挨在一起 |
| 10 | 其他物件密度 | −0.12 | 参考图设备、围栏、箱子更多 |

另有 7 个小权重特征（|w| ≤ 0.09）。不同意的条目告诉我，或直接写进 `app/src/gen/judge/blacklist.json`，重训后它就不再参与评分。

**区分度**：区分“参考图窗口 / 生成图窗口”的交叉验证 AUC 0.766，留出的 100 个种子上 0.772。

**和你的标注对不上**（目标没达到）：每一对（坏标注，好标注）里坏的得分更高的比例，按标注种子留一只有 **0.20**（区域取最高分）/ **0.25**（取平均分），目标是 ≥ 0.7，比随机还差。原因很具体：你标“好”的停车场、大花园、成片绿地，恰恰是生成图特有、参考图里少见的东西；“像参考图”和你的口味在这些标注上方向相反。所以评判器现在能抓到“不像参考图”，但不能代表你的“好 / 坏”。

## 5. 需要你决定的问题
1. **权重表**（第 2 节）有没有你不同意的规律？比如“草地太少”“物件太贴墙”“植物太多”。不同意的进黑名单。
2. **评判器和你的口味相反**（成对准确率 0.20）。要不要继续让它驱动修复？我的建议：exp-02 先保持“实验”，默认关掉；把评判器当作热力图里的提示，继续收集标注（尤其是好标注），等标注够多时让标注的权重压过“像参考图”。
3. **最小降幅**：要不要规定窗口分数至少降 0.05（或降到阈值以下）才采用？可以去掉约四分之一近乎噪声的改动。
4. **整体档**：它对约束和坏标注的效果好得多，但慢（40 秒）而且会改掉好标注。保持默认关，还是只在导出“正式”图时用？
5. **被高层挡住的物件**：评判器现在按“部分可见”计入。要不要只算可见部分超过一半的物件？
