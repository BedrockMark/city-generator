# 实验功能登记

> 规则见 `docs/BRIEF.md`“实验功能（定义）”。代码中的登记表：`app/src/gen/exp.ts` 的 `EXPERIMENTS`，两处保持一致。

## 框架（v0.4.0 起）
- **编号**：`exp-NN`，按申请顺序递增，不复用。
- **开关**：
  - 查看器顶栏“实验 ▾”：总开关 + 逐个开关；URL 参数 `x=0`（总开关关）、`e=exp-01:0,exp-02:1`（逐个）。exp-02 的开关是顶栏的“整体修图”复选框，不在菜单里。
  - 代码：`generate(seed, { experiments, exp: { 'exp-01': false } })`。
- **独立随机流**：实验只从 `expFires(opts, id, rng)` 返回的 `rng.fork('exp/<id>')` 取随机数，所以关掉它时其余随机流不变，同一种子的其余部分尽量不变。
- **触发概率**：登记项可带 `fire(novelty)`，创新度越高越容易触发。v0.7.0 起新登记的实验写成 `fire: fireByNovelty(base)`（`exp.ts`）：创新度 0 时按 base 触发，创新度 1 时总是触发。exp-01 没有 `fire`，开着就总是触发；exp-02 是用户开关，不受创新度影响。
- **证据与建议**（v0.7.0 起，NOTE D49）：`cd app && npx tsx scripts/experiments.ts report` 统计每个实验的好 / 坏标注（区域里有带实验标记的物件）和 A/B 比较（`exp.fire`，流 `exp/<编号>`），写 `src/gen/data/experiments.json`，查看器“实验 ▾”菜单每一行显示。证据 ≥ 8 条且好的比例 ≥ 70% 建议转正，≤ 30% 建议废弃，否则继续观察。只给建议，不自动执行。
- **标记**：实验代码在 `sb.withExp(id, () => …)` 里放置。它产生的物件、小组和区域都带 `exp: '<id>'` 字段，标注层用粉色粗虚线和“实验 exp-NN”标签显示。
- **状态**：实验 → 转正（变成普通生成逻辑，去掉标记，始终开启）/ 废弃（不再运行）。依据是用户对其产物的好 / 坏标注和 A/B 选择，转正或废弃前先向用户确认。
