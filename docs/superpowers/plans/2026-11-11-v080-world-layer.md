# v0.8.0 世界层与街区窗口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 世界种子 → 无限、局部可算的路网（分区噪声 + 主干道 + 支路切分）和世界地面；每个街区通过“窗口”交给现有生成器整块生成；脚本能导出一片城市的大 PNG。

**Architecture:** 新目录 `app/src/world/` 只依赖 `app/src/gen/`（反过来不依赖）。世界层全是纯函数 `(seed, 坐标) → 结果`，随机数来自坐标散列，不依赖计算顺序。街区窗口把世界层的一小块翻译成现有的 `Layout`，`generateBase` 多一个可选参数接收它；不传时一切和 v0.7.9.1 相同。

**Tech Stack:** TypeScript（`tsx --test`、`node:test`、`node:assert/strict`），Python 渲染脚本 `tools/render_generated.py`（`uv run`）。

**Spec:** `docs/superpowers/specs/2026-11-11-v1-city-design.md`（本计划覆盖第 10 节的 v0.8.0 一行：第 2.1、2.3、3.1–3.4、3.8、3.9、4 节；`getChunk`、查看器、特色街区占地、运河、台地在后续里程碑各自的计划里）。

## Global Constraints

- 单街区模式不变：`generate(seed)` 在 200 个回归种子上和 v0.7.9.1 画面、约束记录完全相同（`regress.ts compare` 0 变化）。每个改动生成器的任务都要跑。
- 世界层所有概率、权重、尺寸只在 `app/src/world/config.ts` 里定义为具名导出常量；其它文件不得出现这些数值字面量（spec 3.8）。
- 城市模式不用创新度：`generateBlock` 用常量 `CITY_NOVELTY = 0.10`，`CityOptions` 没有 `novelty`（spec 3.9）。
- 局部性：任何世界层函数的结果只依赖 `(seed, 参数)`；不得有跨调用的可变状态影响结果（缓存可以有，但结果必须和无缓存时相同）。
- 楼上层不超过北边马路的中线（只在城市模式；spec 4）。
- 坐标：世界格坐标是整数，可为负；1 格 = 16 px（`TILE`）。矩形一律半开 `[x0, x1) × [y0, y1)`。
- 代码注释和命名跟现有代码一样：英文注释，中文的 `why` / `reason` 文本。
- 直接在 `main` 上开发；本里程碑结束时一个版本提交 + tag `v0.8.0`（PROGRESS“git”一节）。中间任务的提交是普通提交。
- 测试命令：`cd app && npm test`（`package.json` 的 `test` 脚本要加上 `src/world/*.test.ts`），类型检查 `npx tsc --noEmit`。

## Review Focus

1. **负坐标**：`floor` / 取模在负数上出错（`-1 % 64 === -1`）。期望：`x = -1` 落在主干道格 `i = -1` 或其左边，区块、街区查找和正坐标一样对。→ Task 3、Task 4、Task 6 的测试都含负坐标。
2. **窗口边缘的半截马路**：窗口里被窗口边切断的马路被当成死路 / 不完整的走廊，在窗口边缘生成怪东西（横道、车）。期望：这些物件都落在别的街区的格子上，被归属过滤丢掉；本街区自己的半边车道上的东西和窗口大小无关。→ Task 8 测试“窗口放大 4 格，保留下来的物件不变”。
3. **同一个街区从不同区块 / 不同顺序请求**：缓存命中与否结果不同（全局 id 计数器 `resetIds` 漏掉、缓存里存了被修改过的对象）。期望：逐项相同。→ Task 8、Task 9 测试。
4. **切不开的主干道格**：抖动后某个主干道格的宽或高落进切不开的区间，递归死循环或产出越界街区。期望：总能切开，所有街区内部在 18–40 × 13–28 格里。→ Task 4 测试 30 个种子 × 7 × 7 个格。
5. **相邻两张图的接缝**：两个相邻矩形分别画地面，交界处 autotile / 虚线 / 横道不一致。期望：重叠部分逐格相同。→ Task 6 测试。

### Task 3: 主干道

**Files:**

**Interfaces:**
- Consumes: `hash01`、`hashInt`、`hashPick`、`ARTERIAL_*`
- Produces:
  - `vLine(seed, i: number, j: number): { x0: number; w: number }`：竖向主干道 i 在横向主干道 j 和 j+1 之间那一段的列带 `[x0, x0 + w)`。`x0 = i·SX + 抖动(i) + 段偏移(i, j)`；`w` 只由 i 决定。

段偏移让路口两侧的竖向路错开 0–2 格；路口处横向主干道整条带都是马路，所以错开的两段一定连着。

### Task 4: 支路切分和街区

**Files:**
- Create: `app/src/world/blocks.ts`, `app/src/world/blocks.test.ts`

**Interfaces:**
- Consumes: `cellRect`、`cellAt`、`zoneAt`、`hash*`、`ZONES`、`STREET_WIDTH`、`JOG_*`
- Produces:
  - `cellBlocks(seed, i, j): BlockRec[]`（有缓存，返回冻结的对象）
  - `blockAt(seed, x, y): BlockRec | null`（`null` = 马路）
  - `blockById(seed, id: string): BlockRec`（从 id 里的 `i,j` 找；不存在就抛错）
  - `lotOf(b: BlockRec, x: number, y: number): boolean`：占地里离占地外 > `b.sw` 格（切比雪夫）的格是地块，其余是人行道

切分算法（递归，随机数全部是 `hash*(seed, 'cut', i, j, path, …)`）：

```
zone = zoneAt(主干道格中心)          // 一个主干道格一种分区；过渡发生在主干道格之间
占地范围 = ZONES[zone].lotW/lotH + 2·ZONES[zone].sw
split(rect, path):
  if 宽、高都在占地范围内 && (不能再切 || hash01 < 0.5): 叶子
  可切方向 = 切完两边都“可切开”的方向（feasible(len)：存在 n ≥ 1 使 n·min + (n−1)·STREET ≤ len ≤ n·max + (n−1)·STREET）
  方向按 (边长 / 目标边长)^2 加权抽；位置在合法区间里均匀抽
  JOG_CHANCE：这一刀在中途某处错开 JOG_STEP 格（两段街道带在错开处重叠 STREET − 步长 列，见 spec 3.4）；错开后两侧的每个矩形仍可切开、且将成为叶子的一侧地块外包框仍在范围内才错，否则不错
  左 / 上一侧 path + 'L'，右 / 下 + 'R'
```

每个叶子的 `sw = ZONES[zone].sw`，`paving = hashPick(seed, ZONES[zone].paving, 'blk', id)`，`zone` = 主干道格的分区；`why` 记“主干道格 (i,j) 第 k 刀，竖切于 x=…（宽 … 的一侧在目标范围外）”等。jog 叶子的两个矩形都进 `foot`，`shape: 'jog'`。

### Task 8: 街区窗口和 `generateBlock`

**Files:**
- Create: `app/src/world/window.ts`, `app/src/world/window.test.ts`

**Interfaces:**
- Consumes: `blockById`、`worldCell`、`ownerOf`、`classRaster`、`crossingsIn`、`paintGround`、`findSegs`、`chebDist`、`generateBase`、`withDefaults`、`CITY_NOVELTY`、`WINDOW_MARGIN`、`BLOCK_CACHE`
- Produces:
  ```ts
  export interface CityOptions { prune?: boolean; prefs?: boolean }    // 没有 novelty（spec 3.9）
  export interface BlockScene { scene: Scene; ox: number; oy: number }  // scene 在窗口坐标，(ox, oy) = 窗口左上角的世界格坐标
  export function blockLayout(seed: string, b: BlockRec, margin?: number): { layout: Layout; ox: number; oy: number }   // margin 默认 WINDOW_MARGIN
  export function generateBlock(seed: string, blockId: string, opts?: CityOptions): BlockScene   // 有 LRU 缓存（BLOCK_CACHE）
  export function ownerCell(p: Placed): [number, number]   // 窗口格坐标：有 fp 用 fp 中心，否则 (x + w/2, foot − 1)
  ```

`blockLayout`：窗口 = 占地外包框外扩 `WINDOW_MARGIN`。`cls`：本街区的人行道 / 地块 → `walk` / `lot`，别的街区 → `nwalk` / `nlot`，马路 → `road`；`inP` = 本街区地块；`region` = 别的街区按 id 编号（`regionStyle` = 它们的 `paving`），本街区和马路 −1；`mainStyle` = 本街区 `paving`；`rH = rV = 5`（只在单街区的 `roadMarkings` 里用）；`sw` = 本街区 `sw`，`sw2` = 3；`segs = findSegs(cls, w => [5,7,9].includes(w))`；`crossings` = `crossingsIn` 换成窗口坐标；`base` / `over` / `mark` = `paintGround`；`roadDist = chebDist(马路)`；`shape` = `b.shape`；`topLimit(x)` = 这一列地块最北格往上找到的马路带 `[r0, r1)` 的 `r0 + floor((r1 − r0) / 2)`（找不到马路就 0）。

`generateBlock`：块种子 `` `${seed}/${blockId}` ``；`generateBase(块种子, withDefaults({ novelty: CITY_NOVELTY, ...opts }), { layout, params: { world: { seed, blockId, zone, offset: [ox, oy] } } })`；然后**归属过滤**：`ownerOf(seed, ox + cx, oy + cy) !== blockId` 的物件丢掉，`groups[].members` 去掉被丢的 id，成员空了的小组删掉。
