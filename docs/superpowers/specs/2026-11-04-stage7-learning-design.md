# 阶段 7 设计：从选择中学习 + 创新度

> 2026-11-04。对应 `docs/BRIEF.md` 阶段 7。已和用户确认：
> - 学习方法用方案 A：逐决策点的偏好模型（Bradley–Terry），学的是现有决策点在各上下文下的权重乘子；
> - 数据主要来自**局部 A/B**：同一张图上同时改 4–6 处互不影响的单一决策，用户逐处评价“A 好 / B 好 / 差不多”；
> - 出题两种都要：系统自动出题，以及用户点选物件后发起；
> - 第 1–7 节的详细设计（2026-11-04 对话）整体通过。
>
> 目标版本 v0.7.0。基础：v0.6.1（`stage6` 分支）。

## 1. 目标与验收

**目标**
- 用户的反馈变成**决策权重**，不再变成新规则：A/B 选择和好 / 坏标注 → 每个决策点（`choose` 标签）在各上下文下的选项乘子。
- 实现创新度参数（BRIEF“创新度参数（定义）”）。
- 实验功能的转正 / 废弃流程。
- 说明哪些问题靠选择解决不了，并给出扩展提议空间的方案。

**验收**
1. **不变性**：
   - 偏好关（`l=0`）且创新度 0 时，200 个回归种子的画面和 v0.6.1 完全相同；
   - 偏好表为空时，偏好开也完全相同。
2. **强制决策**：带 `force` 的场景从导出的 JSON 原样重现；不被强制的随机流完全不变（单元测试）。
3. **A/B 出题**：抽查 50 题，每处改动的实际影响都在它自己的框内，不和别的框重叠（溢出率 0）。
4. **学习**：
   - Bradley–Terry 能从模拟数据学回已知乘子（单元测试）；
   - 用户数据上，按出题批次留出的预测准确率写进 `docs/PREFS.md`，目标 ≥ 0.65，达不到如实报告；
   - 乘子表交用户核对。
5. **创新度**：
   - 0 = 完全保守（同验收 1）；
   - 创新度越高，参考图里少用 / 没用过的贴图出现得越多，`novel` 物件在标注层可见；
   - 任何创新度下，硬约束的违规都不比创新度 0 多（200 个种子 × 创新度 0 / 0.5 / 1）。
6. **实验流程**：`scripts/experiments.ts report` 给出每个实验的证据和建议，写进版本报告；不自动执行。
7. **报告**：`docs/v0.7.0.md` 有“选择解决不了的问题”一节，带归类和扩展方案。

## 2. 强制决策（`rng.ts`、`types.ts`）

### 2.1 决策的身份
- 一个决策 = （随机流路径, 标签, 序号 k）。k = 这个流里这个标签第几次被调用，从 0 起。
- **所有调用都计数**，包括之后被 `reject()` 丢掉的提议里的调用。因此 `Trace` 里每个流要有一个按标签的调用计数器，决策记录新增字段 `i`（= k）。被丢掉的提议的决策不在 `decisions` 里，也不能被强制或出题。
- 同一种子、同一份选项（含 `reseed`、`force`、偏好、创新度）下，三元组总是指向同一个决策。

### 2.2 `opts.force`
- `GenOptions.force?: Record<string, string>`，键是 `"<流>|<标签>|<k>"`，值是选项的字符串形式（`show(option)`）。
  - 是否型决策用 `"true"` / `"false"`；`count` 用数字字符串。
- `choose()` / `count()` 遇到被强制的决策：先照常调用 `next()` 消耗一个随机数，再返回字符串形式等于指定值的选项。
  - 指定的选项不在当前选项里时（例如上游变了），不强制，并在 `trace.forceMissed` 里记下这个键。
- 决策记录里加 `forced: true`。
- 被强制的决策之后，同一个流里的抽签照常进行，但路径可能不同（这就是这处改动的连锁）；其他流完全不变。
- 场景 JSON 的 `options.force` 原样保存，导出能重现。

## 3. 局部 A/B

### 3.1 出题（`app/src/gen/learn/ab.ts`，在 Worker 里跑）
1. 生成 A：当前生成器，带偏好和创新度，不开整体修图（A/B 题目一律不开 exp-02）。
2. **候选决策**：A 的决策轨迹里满足以下条件的决策——
   - 有 ≥ 2 个选项，且不是纹理（`tex`）；
   - 结构性决策（`layout` / `block` 流里的、`pack.*`、`bld.modularOrSingle` 这类楼型决策）只作为“大改动”候选（见第 5 步）；
   - 备选项：除当前选项外的某个选项，优先“在这个上下文下数据最少”的那个。
3. **打分排序**：分数 = 不确定性 × 新鲜度 × 重要性。
   - 不确定性 = 1 / (1 + 这个（标签, 上下文）的已有比较数)；
   - 新鲜度：最近 20 题里出现过的标签 × 0.3；
   - 重要性：这个标签的“差不多”比例越高越低，为 1 − 0.8 × 差不多比例。
4. **影响范围**：按排序依次对候选单独生成一次（只强制它一个），和 A 比较画面签名。差异 = 不同的绘制项的外框 ∪ 变化的地面格，向外扩 8px。
   - 没有可见差异的候选丢掉，标签记一次“无影响”。
   - 影响范围的外框大于 12×12 格（192px）就算“大改动”。
5. **组题**：
   - 小改动：贪心挑最多 6 个外框两两相距 ≥ 16px 的候选；
   - 一次最多试 30 个候选（约 30 次生成，3–8 秒），挑不满 4 个也照样出题；
   - 大改动单独成题（每 5 题最多 1 道），布局类决策（`pack.*`、`bld.modularOrSingle` 等）只在大改动题里出现。
6. **验证**：同时强制所有入选的改动生成 B。B 和 A 的差异必须等于各改动单独差异的并集（同样的扩边规则）。不符时，撤掉差异溢出的那处，重新生成 B，直到相符；最后少于 1 处则重新出题。
7. 题目记录：A 和 B 的选项（包括 force）、每处改动的（流, 标签, k, 上下文, A 选项, B 选项, 影响框）。

### 3.2 手动发起
- 标注模式里选中一个物件或区域，按 B：列出放置它的随机流里的决策（标签、上下文、当前选项、备选项），按画面顺序。
- 用户挑一个决策和备选项。两种出法：
  - “只看这一处”：单处改动的题；
  - “再配几处”：以它为第一处，按 3.1 的第 3–6 步补满。
- 用户挑的改动即使是大改动也照样出题。

### 3.3 界面（`app/src/viewer/ab.ts`，快捷键 B 进出 A/B 模式）
- 顶栏显示“A/B 第 n 题 · 出题中…”，以及出题进度。
- **空格**切换显示 A / B；**V** 切换并排（左 A 右 B）。
- 每处改动：编号实线框是影响框；悬停或选中时显示“`yard.parking`（rows=2）：停车场 → 花园”。
- **评价**：数字键 1–6 选中某处，← = A 好，→ = B 好，↓ = 差不多；可在侧栏输入一句备注。没评价的改动不记录。
- **Enter** 保存并出下一题，**S** 跳过这题（不保存），**Esc** 退出 A/B 模式。
- 出题和生成都在 Worker 里（复用 `gen.worker.ts` 的消息机制，新增 `{ id, ab: {...} }` 请求）。

### 3.4 存储（`vite.config.ts` 新增 `/api/choices`）
- `references/choices/v<版本>/seed<种子>_<时间戳>.json`：
  - `{ version, seed, options（不含 force）, novelty, created, kind: 'auto' | 'manual', changes: [{ stream, label, k, ctx, a, b, rect, answer: 'a' | 'b' | 'same', note? }] }`。
- 训练只用（标签, 上下文, A 选项, B 选项, 回答），不需要重新生成，所以旧版本的选择在生成器改版后仍可用。标签或选项在新版本里不存在的，训练时跳过并在报告里计数。

## 4. 学习与应用（`app/src/gen/learn/prefs.ts`、`scripts/prefs.ts`）

### 4.1 模型
- 对每个标签 L 和选项 o，参数 θ(L, o)（对数乘子，全局）；对每个上下文键值 (key=value)，参数 δ(L, key=value, o)。
- 一个决策的选项得分 = θ(L, o) + Σ_ctx δ(L, key=value, o)。乘子 m = exp(得分)。
- 一次比较“o_b 胜 o_a”的概率 = σ(得分(o_b) − 得分(o_a))（Bradley–Terry）。
  - “差不多”= 平局：贡献 −(得分差)² / 2 的损失，权重 0.5，把两者拉向相等。
- **正则**：θ 用 L2 λ_θ = 1，δ 用 L2 λ_δ = 4，都拉向 0（乘子 1 = 原权重）。数据少时自然退回全局乘子，再退回 1。
- **上下限**：应用时乘子截断到 [0.2, 5]，避免某个选项几乎总被选中而变得重复；`PREFS.md` 列出被截断的条目。
- 选项只按字符串比较。是否型决策的选项是 "true" / "false"；`count` 的每个取值是一个选项。
- 不管连续几何（`int` / `range` / `jitter`）；“生成参数”里能写成离散决策或概率的，由 `choose({ p })` 和 `count` 覆盖。
- 训练：牛顿法或 L-BFGS（自己写，不加依赖），参数量 = 出现过的（标签, 选项）+（标签, 上下文, 选项）。

### 4.2 数据
- **A/B 选择**：每处改动一条比较，权重 1。
- **好 / 坏标注**（`references/labels/v0.5.1/` 起）：
  - 场景：v0.5.1 存下的场景 JSON 有 `trace`，但物件还没有 `stream`（阶段 6 才加）。所以用当前生成器、按标注里存的选项（偏好关、无 force）重新生成这个种子，**画面签名和存下的场景相同才用**（exp-02 关时 v0.6.x 和 v0.5.1 画面一致）；不同就跳过这条，在 `PREFS.md` 里计数。v0.6.0 起存的场景自带 `stream`，直接用；
  - 归因：放置了“脚落在标注区域里的物件”的随机流，取它们在轨迹里的决策；被标注的单个物件只取它自己的流；
  - 坏标注：每个决策的已选项，对它的每个备选项各算“输”一次；好标注：算“赢”；
  - 每条标注的总权重 0.3，平均分给它归因到的比较。
- 黑名单 `app/src/gen/learn/blacklist.json`：用户不同意的（标签）或（标签, 选项），训练时去掉。

### 4.3 训练与报告（`npx tsx scripts/prefs.ts train | eval`）
- `train` → `app/src/gen/data/prefs.json`：只存 |log m| ≥ 0.05 的项，`{ label: { global: { opt: m }, ctx: { "key=value": { opt: m } }, n } }`。
- `eval` → `docs/PREFS.md`（由代码生成，不手改）：
  - 数据量：选择题数、比较数、平局数、来自标注的比较数、因标签不存在而跳过的条数；
  - 按出题批次（一个 choices 文件 = 一批）5 折留出的预测准确率（不含平局），以及“总猜 B”的基线；
  - 乘子表：按 |log m| 排序，每条写“`yard.parking`：花园 ×1.8、停车场 ×0.6（12 次比较，上下文 rows=2）”，附一个出现过它的种子和位置；
  - 只有“差不多”的标签单列（“你不在意的决策点”）。

### 4.4 应用（`rng.ts`）
- `GenOptions.prefs?: boolean`（默认 true，查看器复选框“学到的偏好”，URL `l=0` 关）。
- `choose()` 的选项权重（均匀选择视为全 1）乘以 m(L, o, ctx)；是否型决策把赔率 p / (1 − p) 乘以 m(L, "true") / m(L, "false")；`count` 每个取值一个权重。
- 仍然只消耗一个随机数。这个标签在偏好表里没有条目时，走原来的代码路径（保证画面完全不变）。
- 决策记录里加 `m`（实际用到的乘子，只记不为 1 的）。标注层悬停显示“偏好 ×1.8（12 次选择）”。
- 偏好也作用于整体修图里每种打包的生成；整体修图的挑选标准不变（约束不变差 + 怪异分最低）。

## 5. 创新度（`app/src/gen/learn/novelty.ts`）

### 5.1 使用次数
- `tools/export_usage.py` → `app/src/gen/data/usage.json`：`{ key: 次数 }`。次数来源：
  - 参考图里检测到的物件（`work/refworld`，只算 conf=high）；
  - `references/holdout/*.json`（用户存档的合格产出）里的物件。
- 查看器新增“存档为合格”按钮（快捷键 K）：把当前场景 JSON 写进 `references/holdout/v<版本>_seed<种子>.json`（`vite.config.ts` 新增 `/api/holdout`）。
- 次数只由脚本重算，生成器运行时不统计，保证可复现。

### 5.2 偏好少用的贴图
- 适用的决策：选项的字符串形式是 `sprites.json` 里的贴图键（比如 `cars.model`、`front.binModel`），或者是模块楼的部件族。
- 稀有度 r(o) = 1 − log(1 + 次数) / log(1 + 最大次数)，取值 0..1。
- 权重 × (1 + 创新度 × β × r(o))，β = 3。这在偏好乘子之后、抽签之前，只消耗一个随机数。
- 创新度 0 时不改任何权重，走原来的代码路径。
- 选中的贴图在参考图和 holdout 里次数为 0 时，物件 `novel: true`。
  - 标注层：金色虚线框，图例单列“新贴图”，悬停显示“新贴图（参考图里没用过）”。

### 5.3 实验触发
- 现有的 `fire(novelty)` 机制保留。新实验登记时写成 `fire: n => base + n * (1 - base)`。
- exp-01 维持“开着就总是触发”；exp-02（整体修图）是用户开关，不受创新度影响。

### 5.4 评判器放宽
- 窗口怪异阈值 = 原阈值 + 创新度 × 0.2；整体修图的触发线 = 参考图平均分 90 百分位 + 创新度 × 0.1。
- `novel` 物件不计入密度类和重复类特征（`d.*`、`p.*`）。

### 5.5 不变的
- 硬约束（`rationalize`）在之后照常执行，创新度不碰。
- 创新度随导出记录（已有，`options.novelty`）。默认 0.10 会让一部分种子的贴图变化，回归报告列出。

## 6. 实验转正 / 废弃（`scripts/experiments.ts`）
- `report`：每个登记的实验，统计：
  - 好 / 坏标注里，区域内有带这个实验标记的物件 / 区域的条数；
  - A/B 里“有这个实验 vs 没有”的比较（`exp.fire` 是一个是否型决策，可以作为大改动题出现）。
- **建议**：证据 ≥ 8 条且好的比例 ≥ 70% → 建议转正；≤ 30% → 建议废弃；否则继续观察。
- 输出写进版本报告，并显示在查看器“实验 ▾”菜单的每一行（“好 5 / 坏 1，建议转正”）。
- 执行由用户确认后手动改 `exp.ts` 和 `EXPERIMENTS.md`：转正 = 去掉标记、始终开启；废弃 = 不再运行。不自动执行。

## 7. “选择解决不了的问题”报告（`scripts/prefs.ts gaps`）
- 对每条坏标注（v0.5.1 起）做 4.2 的归因：
  - 归因到的决策里，有没有“备选项在模型里得分更高”的？有的话，这条属于“选择能改善”；
  - 没有可换的决策，或者所有备选都不更好：属于“选择解决不了”。
- 把“选择解决不了”的按标注的预设标签和备注归类（太空、方正呆板、太挤、位置不合理……），每类写：
  - 例子（种子、区域截图）；
  - 原因：问题出在打包几何、连续位置还是缺少提议；
  - 2–3 个扩展提议空间的方案（例如非矩形内院、建筑前后错落、斜向小路），每个写改动范围、风险、要不要新的约束。
- 写进 `docs/v0.7.0.md`。用户选中的方案作为新实验（exp-03 起）在后续版本实现，阶段 7 只出方案。

- `rng.test.ts`：强制决策（选中指定选项、只消耗一个随机数、不影响别的流、选项不存在时记 `forceMissed`）；偏好表为空 / 创新度 0 时抽签序列和原来完全相同；乘子按预期改变选择频率（统计检验）。

## 11. 不做的
- 不学连续几何参数（位置、间距、抖动）。
- 不做整图 A/B。
- 不训练更复杂的模型（神经网络、像素特征）。
- 不自动转正 / 废弃实验。
- 不实现第 7 节的扩展方案（只出方案）。

## 12. 风险
- **数据量**：乘子表的质量取决于用户做了多少题。没有数据的决策点保持原样，不会变坏；报告里如实写预测准确率。
- **连锁影响**：上游决策（打包、楼型）一改就是大改动，题目少，学得慢。所以大改动单独出题、限量。
- **决策身份漂移**：生成器改版后，同一个（流, 标签, k）可能指向别的东西。训练只用（标签, 上下文, 选项），不依赖 k；k 只在出题和重现当题时用。
- **偏好让画面趋同**：乘子大时某个选项几乎总被选中，可能变“重复”。由 4.1 的上下限兜住，并用回归里的自我重复指标（`eval_generated.py`）观察。
- **创新度破坏一致性**：稀有贴图可能风格不合。硬约束不受影响；用户可以用坏标注把它压下去（进入偏好学习）。
