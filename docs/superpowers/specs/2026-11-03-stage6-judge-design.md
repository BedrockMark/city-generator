# 阶段 6 设计：局部评判器与修复

> 2026-11-03。对应 `docs/BRIEF.md` 阶段 6。已和用户逐节确认：
> - 怪异以“参考图 vs 生成图”为准；
> - 全在 TypeScript 里做，生成图先降到参考图的视力（方案 1）；
> - 修复分两档，先局部后整体；
> - 修复是实验功能 exp-02，默认开，可以关；另有热力图按钮。
>
> 2026-11-03 补充（用户确认）：地面按颜色对齐；标注只用 v0.5.1 的、用存下的 scene.json；标注与窗口的对应规则；成对准确率按种子留一；整体档单独开关、默认关。
>
> 目标版本 v0.6.0。

## 1. 目标与验收

**目标**
- 给任意地图（生成图或参考图）的每个局部窗口打一个可解释的“怪异分”，输出整图热力图。
- 用换子种子重生成修复最怪的区域；修不好就降级。
- 把评判器学到的规律翻成中文，交用户核对。

**验收**
1. 评判器：
   - 参考图按近重复组留一组交叉验证，AUC 报告在 `docs/reports/JUDGE.md`；
   - 坏标注区域得分高于好标注区域的成对准确率 ≥ 0.7；
   - 权重表经用户核对。
2. 修复：
   - 200 个回归种子上，整图平均怪异分和最怪窗口得分下降；
   - 生效约束的剩余违规不增加；
   - 好标注被改动的情况单独列出。
3. 关掉 exp-02（`e=exp-02:0`）时，200/200 个种子的画面与 v0.5.1 完全相同。

## 2. 评判器（`app/src/gen/judge/`）

### 2.1 窗口
- 8×8 格（128px），步长 4 格（64px）。
- 窗口里有效地面（`ground ≠ 'none'`）不足一半的不用。
- 数据量：
  - 参考图：21 张，约 600 个窗口（全部）；
  - 生成图：回归种子集的前 100 个用来训练，后 100 个用来验证。每张图约 100 个窗口，训练时按参考图窗口数的 3 倍抽样，两类加权平衡。

### 2.2 视力对齐（`align.ts`）
特征只能用参考图里也有的信息。生成图的 `World` 在提特征前先转换：
- **墙**：用整张楼精灵的不透明格（含高层），和参考图的 `building` 格一致。生成图的碰撞体积只用于约束，不用于评判。
- **地面**：参考图的地面类别是按底层图块颜色分的（`semantics.ground_class`：paved 包括内院铺地和广场，不只是人行道），生成图的 `cells` 却是语义类别。所以生成图也按颜色分：Python 用同一规则导出“图块 → 类别”表（`data/tileclass.json`），每格叠加层足够不透明就按叠加层，否则按底图。两边都归成 5 类：马路、铺地、草地、墙、其他（沙、土、水、other）。
- **去掉**：人物、门、区域、`reason` / `gid` 等生成器独有的字段。
- **物件类别**：只保留参考图中出现过的 17 类（`building` 除外），其余并入 `other`，和参考图的 `semantics.py` 分类一致。
- 参考图只用 `conf = high` 的物件。

### 2.3 特征（`features.ts`）
每个特征有 id、中文名，以及“值高意味着什么”的一句话说明。初版约 30 个：

| 组 | 特征 |
|---|---|
| 地面组成 | 马路、铺地、草地、墙、其他各自的面积比例 |
| 密度 | 每类物件数 ÷ 可放置面积（铺地 + 草地 + 其他），按 7 个大类汇总：路缘设施、植物、垃圾、座位、车、标牌、其他 |
| 空地 | 最大空地矩形占可放置面积的比例；离任何物件 ≥32px 的可放置格的比例 |
| 关系 | 同类物件 40px 内成对的比例；参考图高 lift 配对（桌–椅、垃圾–垃圾、树–长椅、红绿灯–红绿灯）的出现率；物件贴墙（≤8px）的比例；物件贴路缘的比例 |
| 重复与节奏 | 同一贴图在窗口内重复的比例；成排等距（3 个以上、间距差 ≤4px）的物件比例 |
| 方正度 | 草地 / 铺地边界中长直线段（≥4 格）所占的比例；每 100 格的转角数 |

特征表是数据，可以增删。用户否掉的特征登记在 `judge/blacklist.json`，训练时跳过。

### 2.4 模型与训练（`scripts/judge.ts train`）
- 模型：逐特征 z-score 标准化，再做 L1 正则的逻辑回归（坐标下降，纯 TS，不加依赖）。
- 标签：参考图窗口 = 0，生成图窗口 = 1。
- 标注并入训练：
  - 只用 v0.5.1 起的标注（用户：旧版本的标注多已无用或重复，阶段全部完成后再大量补充）。
  - 用标注时存下的 `seed*.scene.json` 取窗口，不重新生成（生成器变了，重新生成的画面不是用户标的那张）。
  - 标注范围：有选中物件或框选的，用标注矩形；单击一格（16×16、没有物件）的，用它所在的最小 `yard` / `block` 区域。
  - 窗口与标注范围的重叠面积 ÷ min(标注面积, 窗口面积) ≥ 0.5 时，窗口带这条标注：坏 = 1，好 = 0，权重各 5。
- 正则强度：用留一组交叉验证选。
- 输出 `app/src/gen/data/judge.json`：特征 id 列表、均值 / 方差、权重、截距、阈值、训练日期和数据摘要。
- **怪异分** = 模型输出的概率（0–1，越高越像生成图、越怪）。
- **阈值** = 参考图窗口得分的 90 百分位。

### 2.5 评估（`scripts/judge.ts eval` → `docs/reports/JUDGE.md`，由代码生成）
- 留一组交叉验证的 AUC；验证集（后 100 个种子）上的 AUC。
- 标注成对准确率：每一对（坏区域，好区域）中坏的得分更高的比例。区域得分 = 它对应窗口的最高分。按标注种子留一交叉验证计算（该种子的标注不参与训练），另附训练集上的数字。
- **AUC > 0.97 时报警**：区分得太好，多半是两边视力不同，而不是生成图怪。报告列出贡献最大的特征，供排查。
- 权重表：按 |权重| 排序，每行写“生成图比参考图更 X / 更少 Y”，并附一个参考图窗口和一个生成图窗口的例子。
- 热力图样例：3 个生成种子、2 张参考图。

### 2.6 场景输出
- `scene.judge = { model, windows: [{ rect, score, top: [{ f, contrib }] ×3 }], mean, max }`。
  - `top` 是贡献最大的 3 个特征（权重 × 标准化值），用来解释“为什么这里怪”。
- 生成参考图得分时用同一个函数（`scoreWorld(world)`）。

## 3. 修复（exp-02，`judge/repair.ts`）

### 3.1 换子种子（`rng.ts`、`place.ts`、`types.ts`）
- `GenOptions.reseed?: Record<string, number>`：流路径 → 盐。
  - `Rng.fork(label)` 的路径在 `reseed` 里时，种子串变为 `…/label#盐`，其余流不变。
  - `reseed` 通过 `Trace` 共享给所有分支。
- `SceneBuilder` 给每个放置记下当前流（`Placed.stream`，只写不读）。实现方式：`frontVignettes` 等入口把 `rr.stream` 传给 `sb.inStream()`，与 `withExp` 同样的写法。
- `reseed` 为空时画面不变：回归 `compare` 必须 200/200 相同。

### 3.2 选窗口
- 修复目标：
  - 怪异分超过阈值的窗口；
  - 含有只报告约束（C19、C23、C24）违规的窗口，这些约束在阶段 5 留给“换子种子重生成”解决（D31）。
- 按得分从高到低贪心选取，互不重叠，最多 3 个。

### 3.3 局部档
- 可加盐的流：窗口内物件所属的流，以及窗口内内院块的流（`yard/<kind>x,y`、`yard/park x,y`）。
- 不加盐的流：`layout`、`block`、`neigh`、`yard`（切块本身）、`exp/*`。
- 每个窗口 6 个候选（盐 1..6），每个候选整图重跑 `generate`（含约束修复，不含评判修复）。
- 候选合格的条件：
  1. 生效约束修复后的剩余违规数不比原图多；
  2. 窗口外所有窗口的得分之和变差不超过 0.05 × 窗口数；
  3. 目标窗口的得分低于原分；如果目标是只报告约束，该违规必须消失。
- 合格候选中取目标窗口得分最低的。多个窗口依次处理，后一个窗口在前一个已采用的 `reseed` 基础上叠加。

### 3.4 整体档（单独开关，默认关）
- 开关：`GenOptions.judgeGlobal`，URL `jg=1`。用户决定：评判器区分得好时，几乎每张图都会触发（约 76 次生成），先在回归里测触发率和收益，再决定是否默认打开。
- 局部档做完，整图平均分仍高于“参考图整图平均分的 90 百分位”时，给 `block` 加盐，重新打包主街区。生成 4 个候选，每个候选再走一遍局部档。
- 取整图平均分最低且满足条件 1 的候选。

### 3.5 降级（宁删勿补）
- 局部档一个合格候选都没有、窗口仍超过阈值时，降级：
  - 窗口内的内院块按阶段 5 的方式降级（改草坪 / 只留植物）；
  - 删掉窗口内没有锚点的装饰物。
- 不新增任何物件。降级必须满足条件 1，否则放弃，只记录。

### 3.6 标记与记录
- 采用的候选中，来自加盐流的物件、小组和区域都带 `exp: 'exp-02'`；整体档采用时整张图的主街区都带。降级的区域也带。
- `scene.judgeRepair` 记录：
  - 每个窗口的原分、各候选的得分 / 违规数 / 是否合格；
  - 采用了哪个 `reseed`、降级了什么；
  - 修复前后的整图平均分；
  - 耗时。
- 最终场景的 `options.reseed` 写入采用的盐，所以导出的场景 JSON 可以原样重现（加载时不再修复）。

### 3.7 开关与性能
- 在 `exp.ts` 登记 exp-02，默认开；`docs/EXPERIMENTS.md` 同步登记。关掉时跳过整个修复流程。
- 每张图预计增加 5–15 秒（每次生成约 0.26 秒）。查看器生成时显示“评判修复中…（n / N）”。
- 回归脚本可以并行跑多个进程。

## 4. 查看器
- 顶栏新增“热力图”按钮，快捷键 H。
  - 窗口按得分着色，从透明到红，阈值以上加描边。
  - 悬停显示得分和前 3 个原因（中文特征名 + 方向）。
  - 修复过的窗口显示前后得分。
- 标注层的 exp-02 物件沿用实验样式。
- 导出时，开着热力图会附带 `_heat.png`。

## 5. 回归与报告
- `regress.ts snapshot` 记录 `scene.judge` 的平均分和最高分，以及 `judgeRepair` 的摘要。
- `report` 新增几项：
  - 整图平均怪异分；
  - 最怪窗口的得分；
  - 修复的窗口数、降级数，以及局部档 / 整体档各自的采用次数；
  - 只报告约束（C19、C23、C24）的变化。
- 标注测试照旧。好标注被 exp-02 改动时单独列出。
- 版本报告 `docs/_prev/v0.6.0.md`：
  - 评判器学到的规律（`JUDGE.md` 摘要），等用户核对；
  - 热力图示例；
  - 修复前后对比图；
  - 200 个种子的统计。

## 6. 不做的
- 不改生成规则，也不新增提议种类。
- 评判器不取代硬约束：约束仍由阶段 5 判定和修复；评判修复的候选必须先过约束。
- A/B 选择、决策权重学习、创新度留给阶段 7。
- 不用像素特征，也不用神经网络。

## 7. 风险
- **视力差异被学成“怪异”**：靠对齐、AUC 报警、用户核对权重来控制。
- **换盐后的连锁变化**：放置有先后，后面的层（路缘、车、行人）可能跟着变。靠条件 2（窗口外不变差）限制，并在报告里统计窗口外的物件变化。
- **参考图太少（约 600 个窗口）、主题差异大**：模型只用约 30 个特征和 L1 正则，权重表交用户核对；不适合的特征进黑名单。
- **生成变慢**：exp-02 可以关；回归用并行。
