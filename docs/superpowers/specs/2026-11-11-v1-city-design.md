# v1.0.0 设计：逐块生成的无限城市

> 2026-11-11。BRIEF 的最终目标“生成完整的城市”。基础：v0.7.9.1（`main`）。
>
> 用户已确认（2026-11-11 对话）：
> - 形态：**无限世界，按需流式生成**；任意区块只依赖（世界种子, 坐标）。
> - 宏观结构：**分区噪声 + 两级路网**（主干道 + 支路），有闹市和住宅区的过渡。
> - 交付物：**查看器里可漫游的无限城市 + 可复用的 API**（`getChunk(seed, cx, cy)`）；速度只要求漫游时不明显卡顿。
> - 方案 A：世界路网层 + 每个街区一个“窗口”交给现有的街区生成器。方案 B（全局坐标重写）的唯一实利是跨街区的东西统一处理，用 A 上的“跨街区层”代替。
> - 要有运河和连接两个相邻街区的桥（参考 `references/town_near_river.png`），要有高度（像《红色警戒 2》那样的 2.5D 高度）。
>
> 第 12 节的 5 个问题用户已在 2026-11-11 答复，结论已写进正文。

## 1. 目标与验收

**目标**
- 世界种子 → 无限的城市：路网、分区、街区、运河、桥、高度。
- 每个街区用现有生成器做满（打包、内院、路缘小组、特色街区、约束修复都照常），质量和单街区模式相同。
- 查看器能拖动 / 缩放漫游，后台按需生成；能点进任一街区用现有的标注层和标注工具。
- 生成器提供纯函数 API，以后游戏直接调用。

**验收**
1. **单街区模式不变**：`generate(seed)`（及 `district`）在 200 个回归种子上和 v0.7.9.1 画面、约束记录完全相同（基线 `work/regress/v0791`；本地没有就从 tag `v0.7.9.1` 重建）。每个里程碑都要过。
2. **局部性**：任一区块单独计算和在一大片里计算的结果逐项相同；请求顺序、缓存状态不影响结果（单元测试 + 世界回归）。
3. **接缝**：相邻区块边界上地面、高度逐格一致；每个物件只属于一个街区，只出现一次。
4. **连通**：世界回归区域里，每个街区的人行道步行可达（考虑高度：只能经台阶 / 坡道 / 桥换层），每条马路连在路网上。
5. **街区质量**：世界回归区域里每个街区的剩余约束违规不多于单街区模式的同类统计（按每街区平均比较）。
6. **高度素材**：运河 / 台地素材表能把 `town_near_river` 的运河段和台地段按规则重新铺出来，和原图在可对上的格子里逐格一致（比例写进报告）。
7. **速度**：查看器默认缩放下，一屏从空白到画满 ≤ 5 秒（8 个 Worker），漫游时已加载区域不掉帧。

## 2. 关键决定

### 2.1 生成单位 = 街区，显示单位 = 区块（chunk）
- 街区是语义单位：打包、内院、断头路修复都在一个街区里做。它的形状和大小由世界路网决定，生成时**整块**生成，结果缓存。
- 区块是固定的 64 × 64 格方块（用户确认），只是取数和显示的单位。`getChunk` 返回和这个区块相交的所有东西。
- 一个街区跨几个区块没关系：街区只依赖世界种子和它自己的 id，谁先请求都得到同一个结果。

### 2.2 高度：离散层，屏幕对齐（不做真正的斜投影）
- 每格一个整数层 `h`：v1.0.0 用 −1（运河水面和河底步道）、0（街面）、+1（台地）。数据结构不限层数。
- **画法和参考图、素材一样是屏幕对齐的**：高处的东西画在它自己的格子上，不往上平移；换层的地方画挡土墙。高处朝南的边是 2 行高的墙面（每层），东西两侧和北边是 1 格的墙顶 / 边沿。墙格是单独的格类 `wall`，不能走、不放物件；它占哪一侧的格子由各功能自己定（运河：占河道里的格子，见 3.5；台地：占街区内部最外一圈，见 3.6）。所以“高度”是每格的数据：决定墙面怎么铺、哪里能走、桥怎么搭；画面坐标不变。
- 被否决：《红警 2》式的真投影（`screen_y = y − 2h`）。现有的精灵、楼上层伸出地块、深度排序都假设格子就是屏幕；素材里的台地和桥也是按屏幕对齐画的（`town_near_river` 就是这么拼的）。离散高度下两种画法看起来一样，真投影要改所有绘制和排序。（用户确认：留在自己的格子上。）
- 街区**内部是平的**：一个街区整块在一层上。换层只发生在街区、马路、运河的边界上，现有生成器不用懂高度。

### 2.3 地面归世界，物件归街区
- 马路、人行道、虚线、横道、运河、桥面、挡土墙这些**地面**由世界层直接按格画，不经过街区，所以接缝不可能对不上。
- **物件**（楼、树、车、人、路缘设施……）由街区生成。每个格子有唯一的归属：
  - 街区内部和它的人行道环 → 这个街区；
  - 马路格 → 离它最近的那条人行道所属的街区（切比雪夫距离；一样近时取 id 小的），所以每个街区只在自己这半边车道上停车、放井盖；
  - 路口、运河水面、桥面 → 世界层（v1.0.0 不在上面放物件，桥上的路灯 / 栏杆由世界层画）。
- 街区窗口里生成的、站在别人格子上的物件**丢掉**（按物件的 `foot` 所在格判断）。

### 2.4 特殊高度和跨街区的东西做成实验
- **exp-10 运河与桥**、**exp-11 台地与天桥**按实验规则登记：有编号、可关、产物带 `exp`、在独立随机流上，关掉时其余部分尽量不变。转正前让用户标注。（用户确认。）
- 城市本身（路网、分区、街区窗口）不是实验，是 v1.0.0 的主体。

## 3. 世界层（新目录 `app/src/world/`）

全部是**局部可算**的纯函数：输入世界种子和坐标，内部只用以坐标为标签的随机流（`Rng(seed).fork('world/…', {i, j})`），不依赖计算顺序。

### 3.1 坐标
- 世界格坐标：整数，可以是负数，1 格 = 16 px。原点只是标签，不是起点。
- 主干道格（arterial cell）`(i, j)`：被四条主干道围起来的一大块，约 3 × 3 个普通街区。
- 区块 `(cx, cy)`：`[64cx, 64cx+64) × [64cy, 64cy+64)`。

### 3.2 分区噪声（`zone.ts`）
- 在主干道格的格点上取值噪声（value noise，按 `(i, j)` 散列），双线性插值成连续场 `z(x, y) ∈ [0, 1]`，再按阈值分三种：**闹市**（高）/ **混合** / **住宅**（低）。
- 每种分区一张参数表（`zones.json`，以后可调）：街区目标大小、马路宽度权重、人行道宽、打包的楼型比例、特色街区的种类和概率、台地 / 运河的概率、铺地风格。
- 现有生成器需要新增几个可选参数接收这些（打包比例、马路宽度等），**不传时和现在一样**（验收 1）。

### 3.3 主干道（`arterials.ts`）
- 竖向主干道 `i` 在 `x = i·S + jitter(i)`，横向 `j` 在 `y = j·S' + jitter(j)`。`S` 约 3 个街区宽（约 110–130 格），`jitter` 由散列给出，不超过 ±12 格。
- 每条主干道的宽度（5 / 7 / 9 格）由它自己的散列 + 沿线分区决定，**整条一样宽**，所以路口两边对得上。
- 错位：主干道在相邻两个路口之间可以整段平移 0–2 格（按段 `(i, j)` 散列），路口处出现参考图里那种错位。

### 3.4 支路和街区划分（`blocks.ts`）
- 每个主干道格独立切分：递归地用支路（宽 5 格，两侧人行道）一刀切成两块，直到每块落在分区的目标大小里（内部约 18–40 × 13–28 格，和现有生成器的范围一致）。切的方向按边长加权；每一刀从主干道格的边到边，或从另一条支路到边（T 字路口）。
- 支路的端点在主干道上，**不需要**和隔壁主干道格的支路对齐（参考图里 T 字路口很多）。
- 形状：大多是矩形；一部分切刀在中途错 2–4 格，得到现有生成器认识的 `jog` 形街区。`notch`（带小岛）v1.0.0 不做。
- **特色街区先占地**：切之前按分区概率决定这个主干道格里有没有特色街区，有的话先用 `planCampus(district, 街区随机流)` 求出园区大小，在格里预留一块正好这么大的矩形，再切剩下的部分。宫殿（2–3 个街区大）同样处理，默认权重 0（同 D72），改常量即可打开。所有概率和权重都是常量，见 3.8。
- 街区 id：`b<i>,<j>/<切分路径>`（如 `b3,-2/LRL`），稳定、可读；街区种子 = `<世界种子>/<id>`。

### 3.5 运河（`canals.ts`，exp-10）
- 一部分主干道线变成运河（按线的散列，概率随分区，闹市低、混合高）。运河线不走车：横截面是 人行道 | 墙面 | 水面（3–6 格）| 墙顶 | 人行道，两侧人行道（河岸步道）属于相邻的街区。
- 马路穿过运河的地方：**路桥**（桥面在 0 层，下面是水），世界层画桥面、栏杆、桥头路灯。
- 每隔一段（约 20–40 格，散列）一座**步行桥**，连接运河两岸的两个街区；可能带下到河底步道的台阶（参考图下部）。
- 河底步道（−1 层，紧贴墙面的 1–2 格平台）只在部分河段有，用台阶和岸上连通。

### 3.6 台地与天桥（`terraces.ts`，exp-11）
- 一部分街区（按散列，概率随分区）整块抬到 +1 层：街区内部是 +1，人行道环留在 0 层（停车、公交站仍在街面）。两者之间是挡土墙：南边 2 行墙面，东西和北边 1 格。
- 墙面占的是街区内部最外一圈格子，所以台地街区的可用内部比普通街区小一圈，生成器照常在剩下的部分打包。
- 上下：每个台地街区至少 2 处台阶（南边临街一处，另一侧一处）。**位置由世界层先定**（按散列沿边挑，离街区角 ≥4 格），台阶由世界层画；台阶连同它前后各 1 格作为固定开口传给生成器，生成器在那里开巷子口 / 禁放区，不在上面打包楼。
- **天桥**：两个隔着马路相对的台地街区，按散列在中间架一座 +1 层的步行桥。桥面跨过马路，下面照常走车（参考图左上），桥两头接在台地的边上。天桥由世界层画，两头算两侧街区的禁放区。
- 坡道（马路上下坡）、马路下穿、+2 以上的层 v1.0.0 不做。

### 3.7 高度素材表（`kit.ts`）
- 素材在 `3_City_Props_16x16.png` 第 153–201 行（2026-11-11 用 `town_near_river` 逐格比对找到），只有整合图、没有单张：墙面 / 墙顶 / 柱子、横竖台阶、带栏杆的坡道、桥面上的横竖马路（带虚线）、运河水、路灯桩。
- 做法同 `SLAB_BLOCK` / 树篱：读出每块的作用和拼接规则，写成按四邻 + 层差选块的函数。
- 验证（验收 6）：把 `town_near_river` 的高度标出来，按规则重新铺一遍，和原图逐格比较。

### 3.8 可调常量（`app/src/world/config.ts`）
- 用户 2026-11-11：概率不要写死在代码里。世界层用到的**所有**概率、权重、尺寸都是 `config.ts` 里具名导出的常量（一张表），代码只引用常量名，改一处即生效。至少包括：
  - `CHUNK = 64`；`ARTERIAL_SPACING`、`ARTERIAL_JITTER`、`ARTERIAL_WIDTHS`、`ARTERIAL_JOG`；
  - `ZONE_THRESHOLDS`，以及每种分区的 `ZONES[zone]`：街区目标大小、支路宽、人行道宽、楼型比例、铺地；
  - `DISTRICT_CHANCE`（每种分区一个总概率，默认合起来约 1/8 的街区）、`DISTRICT_WEIGHTS[zone][kind]`（`palace` 默认 0，同 D72）；
  - `CANAL_CHANCE[zone]`、`CANAL_WIDTH`、`FOOTBRIDGE_SPACING`、`QUAY_CHANCE`；
  - `TERRACE_CHANCE[zone]`、`OVERPASS_CHANCE`、`STAIRS_MIN`；
  - `OVERHANG_LIMIT = 'centre'`（楼上层不超过马路中线）；
  - `BLOCK_CACHE = 256`、`WORKERS_MAX = 8`。
- 改常量会改变画面；世界回归报告里写出当前取值。

### 3.9 城市模式不用创新度
- 用户 2026-11-11：城市模式里不需要创新度。城市查看器不显示创新度滑块，`CityOptions` 没有 `novelty`；`generateBlock` 用固定常量 `CITY_NOVELTY`（`config.ts`，默认 0.10，即用户一直审阅的单街区默认画面），新贴图的金框不在城市模式里显示。
- 单街区模式的创新度滑块和 URL `nov=` 保持不变（验收 1）。

## 4. 街区窗口（`app/src/gen/window.ts` + 小改动）

- 窗口**不是**区块：区块固定 64 × 64，是取数和显示的单位；窗口每个街区一个，大小随街区（外包框 + 四周马路 + 对面人行道 + 余量），只在生成这个街区时存在。一个街区可以跨几个区块，一个区块通常含几个街区的一部分。

- `blockLayout(world, blockId) → Layout`：取街区外包框外扩一圈（马路 + 对面人行道 + 2 格），按世界层填 `cls`（本街区 `lot` / `walk`，别的街区 `nlot` / `nwalk`，马路 `road`）、`inP`、`roadDist`、`region`、`segs`、`crossings`（横道由世界层按路口决定，窗口只裁一段）。`base` / `over` 用世界层画好的地面。
- `generateBlock(seed, blockId, opts)`：走 `generateBase` 的同一条流水线，区别只有：
  1. 用 `blockLayout` 代替 `makeLayout`；
  2. 不调 `planNeighbours`、`nfronts`、`island`（邻近街区由它们自己生成）；
  3. `district`、分区参数、固定开口（台阶口、天桥头、步行桥头）由世界层传入；固定开口在打包前作为禁放区刻出来；
     窗口里的运河、墙、桥格在 `cls` 里记成 `nlot`（不能建、不是马路），所以河岸那一侧的人行道没有路缘、不停车；
  4. 最后按 2.3 的归属丢掉站在别人格子上的物件，`rationalize` 在丢之前跑（它要看见窗口里的马路和人行道）。
- 结果是一个普通的 `Scene`（窗口坐标）+ 偏移量，所以现有的标注层、标注工具、约束、渲染都能直接用。场景的 `params` 新增 `world: { seed, blockId, zone, level, offset }`。
- 楼上层伸出地块：单街区模式允许伸到北边马路上（exp-03）。城市里对面就是别人的人行道，**不超过马路的中线**（用户确认）。只在城市模式生效，不影响验收 1。

## 5. 区块 API（`app/src/world/chunk.ts`）

```ts
getChunk(seed: string, cx: number, cy: number, opts?: CityOptions): Chunk
interface Chunk {
  cx: number; cy: number;
  ground: (TileRef | null)[][][];   // 64 × 64，世界层 + 街区的地面改动（车道切路缘、广场铺地等）
  height: number[][];               // 每格的层
  objects: Placed[];                // foot 落在本区块的物件（世界像素坐标），带 blockId
  blocks: string[];                 // 和本区块相交的街区 id
}
getBlock(seed: string, blockId: string, opts?: CityOptions): Scene   // 单个街区的完整场景（标注、导出用）
worldInfo(seed: string, x: number, y: number): { blockId?: string; zone: string; level: number; why: string[] }
```

- 物件按 `foot` 所在格分给唯一的区块，所以不会重复；楼的精灵可以伸到上面的区块里，查看器按行从上往下画区块解决遮挡（见 6）。
- 街区缓存：LRU（默认 256 个街区）。街区的地面改动只在它自己的格子上。
- 全部同步、确定；异步和并行由调用方（查看器的 Worker 池）负责。

## 6. 查看器城市模式

- URL `?city=1&seed=…&x=…&y=…&z=…`，顶栏切换“单街区 / 城市”。单街区模式完全不变。
- 拖动 / 缩放；视野周围一圈区块按距离排队，交给 Worker 池（`min(8, 核数 − 1)` 个）生成；远处的卸载。
- 绘制：每个区块一张地面 RenderTexture，物件按区块所在行合批画到一张向上留出余量（楼高）的 RenderTexture；按区块行从上往下叠，下面一行的东西盖住上面一行。同一行左右相邻区块的物件在边界上可能排序不对（只在伸过边界的大精灵上出现），先接受，在已知问题里记录。
- 悬停显示格子的分区、层、街区；点一个街区高亮它，侧栏显示世界层的说明（为什么这里是主干道、为什么切成这样、为什么是台地 / 特色街区）。
- 双击街区（或按 Enter）进入**单街区查看**：用 `getBlock` 的场景，标注层（A）、好 / 坏标注都照常；标注存到 `references/labels/v<版本>/`，场景名带世界种子和街区 id。Esc 回到城市。
- 导出（E）：当前视野的 PNG，加世界种子、坐标、缩放的 JSON。

## 7. 可解释性

- 世界层的每个决定（主干道位置和宽度、每一刀、分区、特色街区占地、运河、台地、桥）都记一条 `why`，经 `worldInfo` 取到，标注层里可见。
- 街区场景照常有 `gid` / `reason` / `anchor` / 区域；新增的区域类型：`quay`（河岸）、`bridge`、`stairs`、`retaining`（挡土墙），带原因。
- 实验产物（exp-10、exp-11）带 `exp` 字段，标注层用实验样式。

## 8. 约束

- 新增（判定在世界层的连通图上）：
  - C26 街区可达：每个街区的人行道和至少一条马路的人行道步行连通（换层只能经台阶 / 坡道 / 桥）；
  - C27 台阶落地：台阶两头都落在能走的格子上，不被物件挡住；
  - C28 桥两头：步行桥 / 天桥两头接在人行道或台地上；
  - C29 水面上没有物件。
- 修复办法同现在：世界层的修复是**换掉或删掉那座桥 / 那段台阶**，街区里的修复照旧删物件、降级。宁删勿补。

## 9. 回归和测试

- **单街区回归**（验收 1）：`regress.ts snapshot` + `compare`，每个里程碑都跑。
- **世界回归**（新脚本 `scripts/cityregress.ts`）：固定 20 个世界种子 × 每个 5 × 5 个区块（`scripts/city_seeds.json`，只增不改）。报告：
  - 街区大小 / 形状 / 分区 / 特色街区 / 台地 / 运河的分布；
  - 每街区的约束违规和修复（和单街区模式对比）；
  - 接缝检查（验收 3）、连通（验收 4）、局部性（验收 2：同一区域按两种顺序算一遍）；
  - 每街区、每区块的生成时间。
- **单元测试**：主干道 / 切分的局部性；同一街区在不同窗口里 id 和形状相同；归属唯一；高度素材表的选块；`getChunk` 接缝。
- **截图**：`shots.ts` 加城市模式（`--city x,y,z`）。

## 11. 不做（v1.0.0 之后）

马路坡道和下穿、+2 以上的层、高架路；天然河岸、海滩、森林、公园街区；`notch` 小岛街区；曲线路；跨主干道对齐的支路；交通 / 行人模拟；给游戏导出碰撞和寻路数据；动画。

## 12. 用户的答复（2026-11-11）

1. 高度画法：留在自己的格子上（屏幕对齐），不做真投影。
2. 区块 64 × 64 格；区块不是街区窗口（见第 4 节开头）。
3. 特色街区按分区、约 1/8；概率和权重都用常量（3.8）。城市模式不要创新度（3.9）。宫殿默认权重 0，改常量即可。
4. 楼上层不超过马路中线。
5. 运河（exp-10）、台地与天桥（exp-11）先做成实验。
