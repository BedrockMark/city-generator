# app/src/world/

The world layer of city mode (v0.8.0, spec `docs/superpowers/specs/2026-11-11-v1-city-design.md`): zones, arterial roads, street cuts into blocks, per-cell classes and ownership, world ground, block windows that run the single-block generator from [`../gen/`](../gen/README.md), and region assembly. Every function is a pure function of `(seed, world cell coordinates)`: random choices are coordinate hashes, so any part of the world can be computed alone and in any order (NOTE D73). Cells are integers, may be negative, 1 cell = 16 px; rects are half-open. `world/` imports from `gen/`, never the other way round. Single-block mode (`generate(seed)`) does not use this folder.

## Files

| Path | Purpose |
|---|---|
| `config.ts` | Every world tunable as a named constant (spec 3.8): arterial spacing / jitter / widths (11 / 17: two or three lanes each way, every line on its own cell) / lane width / jog, street width, jog chance / step / position / gap, notch islands (`ISLAND_CHANCE`, `ISLAND_LOT`, `ISLAND_ARM`), zone thresholds; lot ranges by prosperity (v0.8.2: `LOT_RANGE` lo / hi ends, `P_LO` / `P_HI` measured zone-value percentiles), `CENTRE_MIN` (44 x 32: big blocks with a centre plaza / garden), special districts per arterial cell (`DISTRICT_CHANCE`, `DISTRICT_WEIGHTS`); per zone sidewalk width, paving and the generator's zone parameters `ZONES[zone].gen` (`mix`, `shopFront`, `composite`, `kit`, `plaza`; tuned values in `docs/reports/v0.8.2.md` 1.4), crossing chances, window margin, pads, `CITY_NOVELTY`, caches. `ROAD_WIDTHS` and `REGION_PAD` are derived. No other file holds these numbers |
| `types.ts` | `Rect`, `ZoneKind`, `BlockRec` (id, cell, footprint rects, sw, zone, paving, shape, why, optional `district` and `centre`), `WorldCell`, `WCrossing` |
| `hash.ts` | Coordinate hash `hash01` / `hashInt` / `hashPick(seed, ...keys)` (cyrb128, as in `gen/rng.ts`) |
| `zone.ts` | `zoneValue` (two-layer smoothstep value noise on the arterial lattice) and `zoneAt` (downtown / mixed / residential) |
| `arterials.ts` | `vLine` / `hLine` (band of an arterial segment, with jitter, width and per-segment jog), `cellRect`, `cellAt`, `arterialWhy` |
| `blocks.ts` | `cellBlocks(seed, i, j)`: recursive street cuts of one arterial cell into blocks (rect or jog), ids `b<i>,<j>/<path>`, cached; a finished rect block may have a corner cut off by a short L-shaped street (`notch`, 0.8.1-hotfix1): the corner is a notch island `<path>I` (shape `island`, made a little square by the generator, no buildings), the rest an L-shaped block (shape `notch`); `blockAt`, `blockById`, `lotOf`. v0.8.2: the cell's lot range is interpolated from its prosperity (`prosperityT`, `lotRange`) and its upper bound widened where the cell cannot be cut (`widenToFit`, `cellLotRange`; why[0] states prosperity and range); a cell may draw a special district (`cellDistrict`), whose campus (`gen/district.ts` `campusFor`) plus sidewalks is reserved in a corner of the cell first (`reserveCorner`: a band, then a piece of it; 4 corners x 2 axes tried) and becomes block `<path>D` with `district` set; a rect non-district block with a lot >= `CENTRE_MIN` is marked `centre` (`garden` in residential, else `plaza`). `feasible` / `Range` are exported |
| `junction.ts` | v0.8.3: arterial jitter / width helpers and `isRoundabout(seed, i, j)` (hash vs `ROUNDABOUT_CHANCE` of the zone at the nominal crossing, without jogs; kept apart from `arterials.ts` / `roundabout.ts` to avoid an import cycle) |
| `roundabout.ts` | v0.8.3 roundabouts (NOTE D102, D103): `Roundabout` (`x0` / `wv`, `y0` / `wh`, `R` = the arterial crossing grown by `ROUNDABOUT_MARGIN` 6 x 5, `island`), `roundabout`, `roundaboutsIn`, `roundaboutAt`; the asset's road / walk table `RB_CLASS` (15 x 13, from `2_City_Terrains`; `tools/export_roundabout.py` re-derives it), `rbSource` (9-slice stretch: the arm column / row repeated), `rbClass`; `islandBlock` (the centre island block `r<i>,<j>`, shape `roundabout`), `roundaboutWhy`. Arterial segments next to a roundabout do not jog (`arterials.ts` `segmentJog`); a corner block loses the road cells of its corner (`BlockRec.cut`) and keeps the rest of `R` as sidewalk (`BlockRec.paved`) |
| `reach.ts` | v0.8.3 C26 (report only, NOTE D104): `blockReach(seed, blockId)` — a zebra's end lands on the block's sidewalk; roundabout islands exempt |
| `cells.ts` | `worldCell`, `classRaster`, `blockRaster`, `cellRange`; road ownership (`roadOwner`, `ownerOf`, `ownerRaster`: nearest sidewalk by Chebyshev distance, smallest id on ties); `crossingsIn` (zebra per junction arm; a junction needs a real cross road, so a jog's widening is none; v0.8.3: a roundabout arm is a junction, keyed `'rb'`, each crossing carries `why`); `rbMask` / `segClasses` (roundabout road cells are not road for `findSegs`, so lane lines, segments and zebras stop at the roundabout) |
| `ground.ts` | `paintGround(seed, r)`: asphalt, autotiled sidewalk / lot paving, lane lines (streets: one dashed centre line; arterials: double solid centre line on `over` plus dashed lane lines), zebras; same tile pickers as `gen/layout.ts`, identical on overlapping rects |
| `window.ts` | `blockLayout` (a block plus `WINDOW_MARGIN` cells, top-left snapped to `SLAB_PERIOD`, as a gen `Layout`, with `topLimit` at the north road centre line, `org` = world origin for stream labels, road segments cut to the block's own stretches and only the crossings it touches, so the block does not depend on the margin), `generateInWindow` (runs `generateBase` with the window, then drops objects / zones on cells the block does not own), `generateBlock` (cached by `BLOCK_CACHE`), `ownerCell`, `zoneCell`, `CityOptions`. v0.8.2: passes the block's `district` as `opts.district` and `city` (zone, `ZONES[zone].gen`, `centre`) in the window |
| `region.ts` | `blocksIn(seed, r)` and `assembleRegion(seed, r)`: one `Scene` for a world rect (world ground + each owner block's ground edits, objects / buildings / groups / zones with `<blockId>:` prefixes, `params.world`) |
| `chunk.ts` | Chunk API (v0.8.1, NOTE D84): `getChunk(seed, cx, cy, opts)` (a `CHUNK` x `CHUNK` = 64 x 64 cell chunk: ground layers taken from the owner block's window, `height` (all 0), objects whose `ownerCell` is in the chunk with block-prefixed ids, `blocks`, `missing`), `getBlock` (a block's full `Scene`), `worldInfo(seed, x, y)` (class, block, owner, zone, `z`, `why[]` for hover), `assembleChunk` (blocks supplied by the caller, used in the viewer's workers), `trimBlock`, `chunkRect`, `chunkOf`. A chunk is a pure function of (seed, cx, cy, options), independent of cache state and request order |
| `*.test.ts` | node:test suites (chunk API included, run by `npm test`): hash, zone continuity and shares, arterial coverage without gaps, cuts in range over 30 seeds x 7 x 7 cells and jog ratio, ownership, crossings, ground seams, window ownership / determinism / cache independence / height limit, region halves vs whole and order independence. All include negative coordinates |

## Usage

`cd app && npx tsx scripts/cityshot.ts ../work/city080 <seed> [x0,y0,w,h]` writes `city_<seed>.json` for a world rect (default `-60,-44,360,264`, about 45 s) and prints block size, zone, jog and violation statistics; render it with `cd tools && uv run python render_generated.py ../work/city080/city_1.json --scale 1`.

World regression (v0.8.1): `cd app && npx tsx scripts/cityregress.ts ../work/cityregress/<name> --jobs 8 --base ../work/regress/<name> [--prev ../work/cityregress/<old>]` builds the 5 x 5 chunks around the origin for 20 seeds with `getChunk`, checks seams / unique ids / locality / road connectivity / sidewalks reach a road, (v0.8.2) lots within their cell's range and centres reachable from the street, and (v0.8.3) roundabouts (no foreign lot in R, arms aligned, island without buildings) and every mall / hotel having its underground car park entrance; reports roundabout counts and C26 (report only); writes `report.md` (distribution by prosperity band, special districts, centres, big blocks' violations; with `--prev` a comparison table against an older run) (about 7 minutes with 8 processes); exit code 1 on a failed check.

Block statistics (v0.8.2): `cd app && npx tsx scripts/blockstats.ts <cmd> [--seeds a,b,...]` with `zone` (zone value percentiles at cell centres, used for `P_LO` / `P_HI`), `districts` (district share and placed / drawn by zone and kind, used for `DISTRICT_CHANCE`), `find` (first example of each district kind, centre plaza and garden, and a typical cell per zone and prosperity band), `fronts` (per zone: main-block buildings, shop-front, single-sprite, kit and street-plaza shares, used to tune `ZONES[zone].gen`).
