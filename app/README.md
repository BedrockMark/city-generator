# app/

The TypeScript / Vite project: a Phaser 3 viewer for the block generator plus the Node (`tsx`) scripts that drive it headlessly. The generator itself lives in [`src/gen/`](src/gen/README.md) and has its own README; this file covers everything else in `app/`. Neighbours: the tileset is linked in from `../assets/` (see [Setup](#setup)), labels go to [`../references/labels/`](../references/README.md), reports to [`../docs/reports/`](../docs/README.md), and the Python render / eval side is [`../tools/`](../tools/README.md).

## Files

### Project root

| Path | Purpose |
|---|---|
| `index.html` | Viewer page: top bar (district select, seed box, 生成 / 重新生成, zoom, 网格 / 虚化, 创新度 slider, 学到的偏好, 标注, 导出截图), `#game` Phaser mount with `#overlay` canvas, `#side` annotation panel; loads `/src/main.ts`. Tooltips name the main shortcuts (Enter, R, F, G, A, E) and the `d=` / `nov=` / `l=0` URL params; the full list is under Viewer reference below. |
| `package.json` | npm manifest `citygen` (private, ESM). Scripts: `dev` (vite), `build` (tsc --noEmit && vite build), `typecheck`, `batch` (tsx scripts/batch.ts), `test` (tsx --test over `src/gen/learn/*.test.ts src/gen/*.test.ts src/viewer/*.test.ts src/world/*.test.ts`). Deps: phaser 3.90; dev: vite, typescript, tsx, playwright-core, @types/node. |
| `package-lock.json` | npm lockfile v3 for `npm ci`. Generated by `npm install`; do not hand-edit. |
| `tsconfig.json` | ES2022 target, bundler resolution, `strict`, `resolveJsonModule` (the `src/gen/data/*.json` manifests are imported directly). `include` lists both `src` and `scripts`, so `tsc --noEmit` checks the CLI scripts too. |
| `vite.config.ts` | Dev server on port 5173 plus the `citygen-labels` plugin: GET / POST `/api/labels` reads and writes `../references/labels/v<version>/seed<seed>.json` (and the labelled `<stem>.scene.json`) for `src/viewer/labels.ts`. Dev server only. |
| `public/assets` | Not in git. A directory junction / symlink to `../assets` so the viewer can load `assets/<file>` (16x16 ground frames, 16x32 character frames). Created once by hand, see Setup. |
| `dist/`, `node_modules/` | Gitignored build output (`npm run build`) and dependencies. |

### `src/` (viewer)

| Path | Purpose |
|---|---|
| `src/main.ts` | The viewer (`class CityView extends Phaser.Scene`): parses URL params, runs `generate()` in the worker, batch-draws ground tiles and sorted sprites into a RenderTexture (optional ghost = translucent building tops), pan / zoom camera, annotation mode, scene-JSON drag-and-drop, and `exportShot()`. |
| `src/viewer/gen.worker.ts` | Module Web Worker: in `{id, seed, opts}`, out `{id, scene}` or `{id, error}`; about 0.3 s per map. A newer request terminates the running worker. |
| `src/viewer/overlay.ts` | Canvas-2D annotation overlay shared by the on-screen layer and the exported `_annotated.png`: zones, building outlines and doors, group boxes, exp (pink) and novel (gold) marks, stage-5 audit (violations red, pruned grey, downgraded purple), labels, selection. Also `pick()`, `zonesAt()`, `buildingOf()`. |
| `src/viewer/labels.ts` | Label model and storage: `GOOD_TAGS` (6) / `BAD_TAGS` (12) preset chips, `sceneStem(scene)`, and `LabelStore` (saves via `/api/labels`, falls back to localStorage key `citygen-labels/<version>/<seed>` when no dev server). |
| `src/viewer/city.ts`, `pool.ts`, `cityqueue.ts`, `city.worker.ts`, `draw.ts` | City mode (v0.8.1): the city view (streaming chunks, hover, block selection, export, block annotation), the fixed-size worker pool, the pure job scheduler, the worker (`block` / `chunk` / `scene` messages) and the drawing helpers shared with the single-block view (each with a `.test.ts` where logic is testable). |
| `src/viewer/mix.ts` | `mixDistrict(seed)`: the viewer's deterministic random district mix. `DEFAULT_MIX` = 20% of seeds, equal weights over district kinds that are neither `exp` nor `menuOnly` (so 宫殿花园 / palace is excluded). The generator never mixes on its own. |
| `src/viewer/mix.test.ts` | Test (node:test) for `mixDistrict`: deterministic, 160..240 of 1000 seeds become districts, every kind appears, custom chance / weights honoured. Run by `npm test`. |
| `src/gen/` | The generator. See [`src/gen/README.md`](src/gen/README.md). |
| `src/world/` | City mode's world layer (v0.8.0): zones, arterials, street cuts into blocks, road ownership, world ground, block windows that run the generator, region assembly. See [`src/world/README.md`](src/world/README.md). |

### `scripts/` (headless CLI, run from `app/` with `npx tsx scripts/<name>.ts`)

| Path | Purpose |
|---|---|
| `scripts/batch.ts` | `batch.ts <outDir> <seed\|a..b> ... [--d=<kind>]`: writes `<outDir>/scene_<seed>.json` (or `scene_<kind>_<seed>.json`) per seed and prints size, object count and ms. Input for `tools/render_generated.py` and `tools/eval_generated.py`. |
| `scripts/regress.ts` | Regression harness over the fixed seed set: `snapshot`, `snapshot-par`, `compare`, `report`, `labels`, `explain` (usage below). Snapshots go to gitignored `../work/regress/<name>/`. |
| `scripts/labeltests.ts` | Library used by `regress.ts report` / `labels`: replays every label in `references/labels/v*/seed*.json` against the current generator with the label's recorded options; bad labels pass when the thing is gone, good labels warn when changed. No CLI of its own. |
| `scripts/constraints.ts` | `constraints.ts gen [n] \| refs \| doc [n]`: violations per constraint on the first n regression seeds; the same on `../work/refworld/*.json`; or both written to `docs/reports/CONSTRAINTS.md` (generated, do not edit). |
| `scripts/prefs.ts` | `prefs.ts train \| eval \| gaps`: fit the Bradley-Terry preference table into `src/gen/data/prefs.json`; write `docs/reports/PREFS.md` (generated); or score every bad label against a leave-seed-out model into `work/gaps/`. |
| `scripts/shots.ts` | `shots.ts <outDir> [--anno] [--q=<url params>] <seed\|a..b> ...` (also `shots.ts <outDir> <worldSeed> --city x,y,z [--city ...]` for city mode views: writes `ui_city_<seed>_<x>_<y>_<z>.png` and the exported `citygen_v<ver>_world<seed>_x<x>_y<y>_z<z>.png` / `.json`): drives the running viewer in headless Microsoft Edge (playwright-core, swiftshader WebGL); writes `ui_seed<first>.png` (and `ui_anno_seed<first>.png` with `--anno`) for the first seed only, then clicks 导出 for every seed and saves the export files into `<outDir>`. |
| `scripts/cityshot.ts` | `cityshot.ts <outDir> <seed> [x0,y0,w,h]` (default `-60,-44,360,264`): assembles a world rect from `src/world/` into `<outDir>/city_<seed>.json` and prints block size / zone / jog / violation / timing statistics (about 45 s). Render with `tools/render_generated.py`. |
| `scripts/cityregress.ts` | `cityregress.ts <outDir> [--seeds a,b,...] [--jobs n] [--locality k] [--base <regress snapshot dir>]`: world regression (v0.8.1). Per seed the 5 x 5 chunks `cx, cy in [-2, 2]` are built with `getChunk` and checked (seams equal `assembleRegion`, unique object ids, locality after cache clear / reverse order for the first k seeds, road connectivity, sidewalk next to road); writes `<outDir>/<seed>.json` and `report.md`; exit 1 when a check fails. Default seeds `scripts/city_seeds.json` (1..20). About 7 minutes with `--jobs 8`. |
| `scripts/city_seeds.json` | The world regression seed list (1..20). |
| `scripts/seeds.ts` | Exports `SEEDS: string[]` read from `regression_seeds.json`; imported by `regress.ts`, `constraints.ts`, `prefs.ts`. |
| `scripts/regression_seeds.json` | The fixed regression seed set: 200 seeds = 12 user-reported seeds (8, 44522, ...) followed by 1..189 (8 not repeated). Append-only so old snapshots stay comparable. |

## Setup

1. Put the tileset at `<repo>/assets/` (it is not part of this repository).
2. Link `app/public/assets` to it (gitignored; do this once):
   - Windows cmd: `cd app\public && mklink /J assets ..\..\assets`
   - Windows PowerShell: `New-Item -ItemType Junction -Path app\public\assets -Target (Resolve-Path assets)` (from the repo root)
   - Unix / Git Bash with symlinks: `ln -s ../../assets app/public/assets`
   - Check: `ls app/public/assets` lists the tileset folders.
3. `cd app && npm ci` (Node 24 / npm 11 verified; `npm install` also works).

## Commands

All from `app/`.

| Command | What it does |
|---|---|
| `npx vite` (or `npm run dev`) | Dev server on http://localhost:5173/?seed=7 ; also enables `/api/labels` so labels are written to disk. |
| `npm run build` | Typecheck, then `vite build` into `dist/` (gitignored, no labels API). |
| `npx tsc --noEmit` (or `npm run typecheck`) | Typecheck `src/` and `scripts/` (about 3 s). |
| `npm test` | node:test suites via tsx: 21 files, 104 tests, about 1 min. |
| `npx tsx scripts/batch.ts ../work/gen 1..12` | Headless scenes `../work/gen/scene_1.json` .. `scene_12.json`; add `--d=gas` (or school, hospital, police, fire, mall, hotel, palace) for a district. Then `cd ../tools && uv run python render_generated.py ../work/gen/scene_1.json --scale 1` renders a PNG. |
| `npx tsx scripts/regress.ts snapshot <dir> [--pd] [--nov <x>] [--noprefs] [--shard k/n]` | Per seed: `<seed>.json` (visual signature), `<seed>.learn.json`, `<seed>.audit.json`, plus `index.json`. `--pd` = draft repairs on. |
| `npx tsx scripts/regress.ts snapshot-par ../work/regress/<name> --jobs 8` | Same snapshot in parallel processes; about 40 s for 200 seeds. |
| `npx tsx scripts/regress.ts compare <dirA> <dirB>` | Lists seeds whose picture changed; exit 1 if any. |
| `npx tsx scripts/regress.ts report <dirA> <dirB>` | Picture changes, per-constraint violation / prune counts, novelty and prefs stats, timing, and the label tests replayed in B's mode. |
| `npx tsx scripts/regress.ts labels [--pd]` | Label tests only; exit 1 if a bad label is still reproduced. |
| `npx tsx scripts/regress.ts explain` | Checks every object has gid / reason / anchor and every random draw is labelled. |
| `npx tsx scripts/constraints.ts gen [n]` | Constraint violation statistics on the first n regression seeds. `refs` and `doc [n]` need `../work/refworld/` from `tools/export_refworld.py`. |
| `npx tsx scripts/prefs.ts train` | Rewrites `src/gen/data/prefs.json` (idempotent). `eval` writes `docs/reports/PREFS.md`; `gaps` shells out to `uv run python crop_region.py` in `../tools`. |
| `npx tsx scripts/shots.ts ../work/shots [--anno] [--q=d=school] 2 3 5` | Needs `npx vite` already running (set `PORT=<n>` if not on 5173) and Microsoft Edge installed. About 12 s per seed; waits up to 180 s. |

## Viewer reference

- City mode (v0.8.1): button 单街区 / 城市 in the toolbar, or `?city=1&seed=<world seed>&x=<cell>&y=<cell>&z=<zoom>`. Drag = pan, wheel = zoom (0.25..4), hover = `(x, y) · zone · level · block` in the info bar, click = select / unselect a block (opens a panel with the why lines; `Esc` unselects), double-click or `Enter` (or 进入街区) = enter the selected block (press `A` for the annotation layer; good / bad labels saved per world seed and block id), `Esc` = back to the city, `E` = export a snapshot of the current screen (PNG + JSON), `F` = back to the default zoom. Chunks (64 x 64 cells) are generated in a worker pool; `src/world/chunk.ts` is the API. See `docs/reports/v0.8.1.md`.
- Keyboard: `R` random seed and regenerate, `F` fit to window, `E` export, `A` toggle annotation mode, `G` toggle ghost (translucent building tops), `1` / `2` mark the selection good / bad (annotation mode only), `Esc` unpin the selection, `Enter` in the seed box generates, `Ctrl+Enter` in the label textarea saves the label.
- Mouse: drag = pan, wheel = zoom by 1.25x steps (clamped 0.25..8); in annotation mode click = select / pin an object or an empty point ("why is this empty"), `Shift`+drag = box-select a region. Drag-and-drop a scene JSON file onto the page to view it as saved.
- URL params: `seed=<string>` (random 0..999999 if absent), `nov=<0..1>` novelty, `p=0` pruning off, `l=0` learned preferences off, `d=school|hospital|police|fire|mall|hotel|gas|palace|none` (`none` = plain block only; absent = the random mix). The URL is rewritten with `history.replaceState` after each generation.
- District menu: 普通街区 (random mix via `mix.ts`), 只要普通街区 (`d=none`), then 学校 / 医院 / 警察局 / 消防站 / 购物中心 / 酒店 / 加油站 / 宫殿花园. Kinds flagged `exp` in `src/gen/district.ts` get an `[exp] ` prefix; `menuOnly` kinds (palace) are never drawn by the mix.
- Export (`E` or 导出截图): `citygen_v<version>_<stem>` where `stem = seed<seed>[_n<novelty>][_p0][_pd1][_l0][_d<kind>]`; files `.png` (2x), `_ghost.png` (2x), `_annotated.png` (3x with overlay), `.json` (scene), and `_labels.json` when labels exist.
- Overlay colours: experimental objects pink `#ff2bd6`, novel sprites gold `#ffc107`, good label `#36d36b`, bad label `#ff4040`, audit violation `#e53935`, downgraded zone `#8e24aa`. Zone layers: keepclear / yard / curb / road / block.

## Notes

- `package.json` version `0.1.0` is not the project version. The generator's `VERSION` (`0.8.0` in `src/gen/generate.ts`) is what appears in export filenames, label folders and snapshots.
- Without the `public/assets` link the viewer shows nothing (every texture load 404s); the scripts still work because they never load images.
- Labels persist to `../references/labels/` only while `npx vite` is running; a production build has no API and labels stay in localStorage (the label form shows `保存到 references/labels/` when the dev server answered, `开发服务器不可用：暂存浏览器` otherwise).
- Commands that reach into `../tools/` (`render_generated.py`, `prefs.ts gaps`, `constraints.ts refs` / `doc`) need the Python environment first: `cd tools && uv sync` (see [`../tools/README.md`](../tools/README.md)). The viewer, `npm test` and the other scripts do not need Python.
- Scripts always call `generate(seed)` with no district unless told (`--d=` in batch, or the label's recorded options). Only the viewer applies the 20% random mix, so regression snapshots are plain blocks.
- Scripts resolve repo paths relative to their own file, but `outDir` arguments are relative to the cwd, so run them from `app/`.
- `../work/` is gitignored: `work/gen`, `work/regress`, `work/shots`, `work/gaps`, `work/refworld` are all local. A fresh clone has no regression baseline; snapshot one first, then `compare` against it after changes.
- `regress.ts`: the header comment omits `explain` and the usage string omits `snapshot-par`; both subcommands exist.
- `vite.config.ts` ends with a comment mentioning `public/data`; no such folder exists. All manifests are bundled from `src/gen/data/*.json`.
- `shots.ts` prints one `[page error] ... 404` per run: that is `/favicon.ico`, harmless.
